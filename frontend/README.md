# Интерфейс — этап 7

Интерфейс работает вместе с FastAPI по одному адресу. Оформление обновлено
по бордово-розовому референсу: отдельная боковая панель, крупный заголовок,
белые карточки и понятные состояния проверки. Касымбек отвечает за интерфейс
и сервер, Данияр — за анализатор.

## Рекомендуемый запуск для демонстрации

На новом компьютере используйте отдельное окружение приложения:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\demo.ps1 -Install
```

Повторный запуск — без `-Install`. Откройте <http://127.0.0.1:8000> и выберите
созданный нейтральный файл `backend/.local/demo/sample.mov`. Скрипт использует
`.venv-app`, запускает только тестовый режим и не меняет `.venv` анализатора.
Подготовка, автоматические проверки и показ за 3–4 минуты описаны в
[руководстве демонстрации](../docs/DEMO_GUIDE.md).

## Показ по внешней ссылке — этап 9

`scripts/public.ps1 -Install` запускает интерфейс и API по одному временному
HTTPS-адресу через Cloudflare Quick Tunnel. Откройте ссылку, которую напечатает
скрипт после готовности. Внешний профиль по умолчанию работает в `mock` и
принимает MOV до 90 МиБ; актуальный предел приходит от сервера.

После перезапуска туннеля адрес меняется. Cookie и восстановление проверки
привязаны к прежнему адресу и автоматически на новый не переносятся. Для
сетевого показа используйте только нейтральные синтетические видео.
Подготовка и проверка с другого устройства — в
[руководстве внешнего доступа](../docs/PUBLIC_ACCESS.md).

## Прямой запуск

Из корня репозитория, в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\backend\start.ps1 -Mode mock
```

Откройте <http://127.0.0.1:8000>. На новом ноутбуке добавьте к первой команде
`-Install`. Отдельный frontend-сервер, Node.js и сборка не требуются.
Остановка — Ctrl+C. Старый скрипт `frontend/preview.ps1`
теперь запускает тот же сервер; для проверки передайте ему `-Mode mock`.

Прямой запуск и команды следующего раздела используют `.venv` и
`backend/.local`; для отдельной демонстрационной среды следуйте руководству выше.

## Проверка полного пути

1. Создайте нейтральное видео командой `.\.venv\Scripts\python.exe -m backend.make_sample`.
2. Дождитесь сообщения о готовности сервера на странице.
3. Выберите `backend/.local/sample.mov` либо перетащите его в область загрузки.
4. Передача начнётся автоматически. Процент относится только к передаче файла;
   после неё сервер проверяет видео, затем выполняет анализ.
5. Дождитесь результата: вердикта, списка событий и кадров. Кнопки «Ответ» нет.
6. Выберите событие в списке: справа появятся полное объяснение и 1–3 кадра.
7. Нажмите на кадр, чтобы увеличить его. Кнопки просмотра переключают кадры
   текущего события; Escape закрывает окно и возвращает фокус.
8. Нажмите на таймкод события или кадра, чтобы перейти к нему в исходном видео.
   Воспроизведение запускается вручную; звук изначально выключен.
9. Нажмите «Проверить другое видео», чтобы очистить результат и выбрать новый файл.

**Режим mock возвращает синтетические ответы и кадры. Содержимое видео модель
не анализирует.** Это явно указано в шапке, уведомлении и результате.

Для разных сценариев перезапустите сервер с `-Scenario clean`
(нет нарушений), `-Scenario one` (одно), `-Scenario multiple`
(два) или `-Scenario error` (ошибка).
Реальный анализ включается командой `-Mode real` после подключения
модуля Данияра; при отсутствии анализатора выбор файла будет недоступен.

## События, таймкоды и кадры

События упорядочены по времени. Названия типов не ограничены списком на frontend;
объяснение отображается полностью, включая переданный анализатором нормативный
источник и переносы строк. Интерфейс не добавляет правовые выводы и не превращает
текст результата в HTML.

Время показано с миллисекундами: `00:01.500`, для длинных видео — `01:02:03.500`.
У каждого кадра свой таймкод. Кадры отображаются целиком, без обрезки; ошибка
декодирования изображения имеет отдельное сообщение. Тестовые изображения
помечены как синтетические и не выдаются за кадры загруженного видео.

Плеер использует выбранный файл из памяти браузера. Для просмотра он не скачивает
видео с сервера повторно. Поддержка MOV зависит от кодека и браузера: если файл
не воспроизводится, список событий, объяснения и кадры остаются доступны.
Время за пределами длительности не подменяется ближайшей точкой: интерфейс
сообщает, что перейти к нему нельзя.

При результате без нарушений показано понятное пустое состояние. Техническая
ошибка не получает карточки вымышленных событий. При новой проверке предыдущий
результат и ссылки на локальное видео очищаются.

## Поведение при ошибках

Проверяются один файл, расширение MOV, непустой размер и лимит, полученный
от сервера. Сервер дополнительно декодирует первый кадр, поэтому переименованный
текстовый файл не считается видео.

Во время отправки и анализа повторный выбор заблокирован. Запросы статуса
выполняются последовательно. После ограниченного числа сетевых ошибок или
истечения времени появляется ручная проверка статуса того же задания.
При неопределённом исходе POST ручной повтор сохраняет идентификатор загрузки;
автоматической повторной отправки видео нет. Ошибка анализа не является
вердиктом «нарушений нет».

Тот же ролик можно проверить заново: нажмите «Проверить другое видео»
или «Начать новую проверку» и выберите его ещё раз. Это отдельное задание.
Если подтверждение загрузки потерялось, сначала используйте «Проверить состояние
загрузки». Ручная кнопка «Повторно отправить файл» появляется, когда сервер
не нашёл принятую загрузку и исходный файл ещё доступен на открытой странице.
После F5 файл потребуется выбрать заново, если нужно создать новую проверку.

## Восстановление проверки

В том же браузере и по тому же адресу сайта последняя проверка восстанавливается
после F5, закрытия вкладки или повторного открытия страницы. Сначала обновляется
браузерная сессия, затем запрашивается уже созданное задание. Это работает и при
недоступном анализаторе: для чтения готового результата повторный анализ не нужен.

В `localStorage` сохраняются только идентификаторы загрузки и задания, режим,
время начала и свойства файла: имя, размер и дата изменения. Видео, изображения,
описания событий, API-ключ и CSRF-токен туда не записываются. Хранится одна последняя
проверка; новая проверка заменяет её. Очистка данных браузера или истечение сессии
может сделать восстановление недоступным. При запрете локального хранилища обычная
загрузка продолжает работать, но восстановление после закрытия страницы не гарантируется.

Если страница закрылась до получения `job_id`, приложение сначала ищет принятую
загрузку по её прежнему идентификатору. Пока запись ещё не появилась, можно повторить
проверку её состояния. Отсутствие записи в этот момент не доказывает, что сервер
не получил файл. Автоматического повторного POST нет. Начало новой проверки при
неизвестном исходе предыдущей отмечается отдельным предупреждением.

После восстановления отчёта события и JPEG-кадры доступны сразу. Для видеоплеера
нажмите «Выбрать исходное видео» и укажите тот же MOV. Этот выбор используется только
локально, не отправляет файл на сервер и не создаёт новое задание. Сверяются имя,
размер и известная дата изменения; совпадение этих свойств не доказывает идентичность
содержимого. Если кодек не поддерживается браузером, события и кадры остаются доступны.

Сохранённый режим конкретного задания берётся с сервера. Старый тестовый отчёт
остаётся тестовым даже при переключении приложения в `real`. При неизвестном режиме
старой записи вывод не показывается как настоящий анализ. Неизвестное или удалённое
задание, истёкшая сессия и техническая ошибка имеют отдельные сообщения.

## Соединение с сервером

- GET `/ui/session` — режим, готовность, лимиты и CSRF-токен.
- POST `/ui/analyze` — multipart `file`, CSRF и идентификатор загрузки.
- GET `/ui/jobs/{job_id}` — статус и результат своего задания.
- GET `/ui/recovery/{upload_id}` — поиск принятой загрузки и её метаданных для восстановления.

Браузер использует HttpOnly cookie; ключ публичного API в JavaScript не
передаётся. Страница и запросы должны идти с одного адреса.
Публичный `/api/v1/*` предназначен для прямой проверки с X-API-Key.

## Проверки

Проверки результата, локального выбора видео, хранилища восстановления и переходов
интерфейса запускаются стандартным тестовым модулем Node.js, без npm-пакетов:

```powershell
node --test frontend/tests/*.test.cjs
```

Для использования самого сайта Node.js не нужен. В браузере проверьте сценарий
`multiple`: два события, три кадра первого события, один кадр второго, увеличение,
переключение кадров и переход к `00:01.500`. Затем `clean` и `error`: пустой
результат и техническая ошибка должны выглядеть по-разному.

Дополнительно проверьте восстановление в браузере:

1. Для заметного ожидания задайте `$env:CASH_AUDIT_MOCK_DELAY_SECONDS = '15'` перед запуском тестового сервера. Загрузите нейтральный MOV, дождитесь сообщения о принятии и нажмите F5: номер задания должен сохраниться.
2. После готового отчёта закройте вкладку и снова откройте тот же адрес. События и кадры должны восстановиться. Выберите исходный файл для плеера: новое задание создаваться не должно.
3. Во время ожидания временно отключите сеть во вкладке через инструменты разработчика. После ограниченных повторов должна появиться кнопка запроса результата. Верните сеть и продолжите ожидание того же задания.
4. Проверьте `-Scenario error`: после F5 ошибка остаётся ошибкой, без вердикта «нарушений нет».
5. Очистите cookie сайта при сохранённой проверке: приложение не должно открыть результат прежней сессии.

Автоматические проверки DOM используют тестовое окружение Node.js. Они не подтверждают
поддержку видеокодеков, нативный диалог выбора файла или внешний вид конкретного браузера.

## Границы этапа

На странице показаны статус задания, итоговый вердикт, события, нормативное
объяснение из ответа анализатора, кадры и исходное видео. Восстанавливается одна последняя
проверка, пока доступны запись на сервере и её браузерная сессия. История всех проверок
и синхронное управление одной загрузкой из нескольких вкладок в этот этап не входят.
Полноценное подключение и оценка реальной модели выполняются отдельно.

`index.html` — структура и встроенные SVG; `styles.css` —
основное оформление; `app.js` — состояние загрузки и сетевые запросы;
`recovery.js` — ограниченное локальное хранилище последней проверки;
`results.js` и `results.css` — подробный результат и просмотр кадров.
Внешние шрифты, CDN и облачный анализ не используются.
