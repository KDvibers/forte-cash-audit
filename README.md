# Forte Cash Audit

Проект команды KDvibers для кейса ForteBank: загрузка кассового видео, локальный анализ и результат с возможными нарушениями, временем события и подтверждающими кадрами.

Этап 1 выполнен: модель запущена локально на RTX 5070 и проверена на видео. Скорость и расход памяти измерены; выявлены существенные ошибки понимания последовательности. Приложение и окончательный анализатор нарушений ещё не готовы. Результаты и инструкция запуска: [analyzer/README.md](analyzer/README.md).

## Этапы и условия готовности

1. **Локальный запуск.** Загрузить готовую модель на RTX 5070, проверить несколько видео, записать скорость, расход памяти и реальные ошибки. Дообучение на этом этапе не проводится.
2. **Наблюдения по видео.** Получать действия и состояния с временными отметками; проверять качество на разных сценах и ракурсах. Решение о дообучении принимать по измеренным ошибкам.
3. **Правила и доказательства.** Соединить наблюдения с условиями правил, проверить нормативные ссылки, выдавать возможное нарушение, время и настоящие кадры. Подготовить `analyze_video(video_path)` по согласованному контракту.
4. **Интеграция.** Соединить анализатор с интерфейсом и сервером друга, проверить путь от загрузки MOV до отчёта и публичный API с ключом.
5. **Проверка перед сдачей.** Оценить качество и временные отметки без смешивания дубликатов между частями выборки, проверить полный лимит времени, воспроизводимый запуск, подготовить демонстрацию и описать ограничения. Уже просмотренный открытый набор не является независимым скрытым тестом.

Друг параллельно разрабатывает интерфейс и сервер по контракту, используя явно обозначенные тестовые ответы. После завершённого и проверенного этапа готовим отдельный PR; push и создание PR выполняет только Ергали. Из `main` получены сервер и предпросмотр интерфейса.

Инструкция существующего сервера: [backend/README.md](backend/README.md). Реальный анализатор `analyzer.service.analyze_video` пока не реализован, поэтому режим `real` ещё не готов к обработке видео. Тестовый режим сервера включается явно. До интеграции зависимости сервера и анализатора проверяются раздельно; версии Pillow в их текущих требованиях различаются.

## Предпросмотр интерфейса

Из корня репозитория, в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\frontend\preview.ps1
```

Откройте <http://127.0.0.1:4173>. Доступны выбор MOV, перетаскивание, проверка имени и размера, замена файла и справка. Файл остаётся в памяти текущей страницы: интерфейс пока не отправляет видео на сервер и не запускает анализ. Сервер API для предпросмотра не нужен.

- [Интерфейс и ограничения предпросмотра](frontend/README.md).
- [Сервер, API и его отдельный запуск](backend/README.md).

Frontend не требует Node.js, установки пакетов или сборки. Для команды предпросмотра нужен Python; остановка сервера — `Ctrl+C`.

Нумерация этапов в инструкции интерфейса относится к его отдельному плану и не совпадает с общими этапами проекта выше.

## Разделение работы

- Ергали и ассистент: анализатор видео, локальная модель, правила, нормативные ссылки, кадры-доказательства и проверка качества в `analyzer/`.
- Друг: весь интерфейс в `frontend/` и сервер приложения в `backend/` — загрузка, задания, статусы и API. Экран результатов тоже делает друг. Подробная задача: [docs/TEAMMATE_TASK.md](docs/TEAMMATE_TASK.md).
- Вместе: соединение частей, развёртывание и проверка на ноутбуке Ергали с RTX 5070.

## Совместная работа

Работаем в отдельных ветках без префикса `codex/`: `analyzer` и `web-api`. Текущая локальная ветка — `analyzer`. Изменения перед объединением просматриваем. Push и создание PR выполняет только Ергали; агенты готовят локальные изменения. Для отправки с его компьютера проверяется аккаунт `yergaliuly`. Друг передаёт подготовленные изменения Ергали без публикации агентом.

Единый формат обмена между частями записан в [docs/API_CONTRACT.md](docs/API_CONTRACT.md). Анализатор возвращает смысловой результат, сервер добавляет номер задания и статус. Друг начинает с обозначенных тестовых ответов, не ожидая готовности модели.

Код хранится в GitHub. Обработка видео выполняется на оборудовании, где запущен наш backend с локальной моделью. Наличие репозитория само по себе не запускает обработку и не публикует приложение.

Видео, таблица разметки, извлечённые кадры, веса моделей и секреты остаются вне Git. Локальные заметки по исходным видео находятся в исключённой из Git папке `review/`.
