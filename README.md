# Forte Cash Audit

Проект команды KDvibers для кейса ForteBank: загрузка кассового видео, локальный анализ и результат с возможными нарушениями, временем события и подтверждающими кадрами.

Интерфейс и сервер соединены: выбор MOV автоматически запускает загрузку, ожидание и вывод общего результата. Реальный анализатор `analyzer.service.analyze_video` пока не реализован; для проверки приложения используется явно обозначенный тестовый режим.

Этап 1 анализатора выполнен: модель запущена локально на RTX 5070 и проверена на видео. Скорость и расход памяти измерены; выявлены существенные ошибки понимания последовательности. Окончательный анализатор нарушений ещё не готов. Результаты и инструкция запуска: [analyzer/README.md](analyzer/README.md).

## Запуск интерфейса и API — этап 4

До интеграции зависимости сервера и анализатора проверяются раздельно: версии Pillow в их текущих требованиях различаются. Не устанавливайте требования backend поверх рабочего окружения анализатора без согласования зависимостей; подробности — в [analyzer/README.md](analyzer/README.md).

Из корня репозитория, в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\backend\start.ps1 -Mode mock
```

Откройте <http://127.0.0.1:8000>. Выберите или перетащите MOV: файл автоматически отправится на сервер, после чего появятся состояние проверки и итоговое заключение. Интерфейс и API работают в одном процессе, отдельный сервер frontend не нужен.

- [Интерфейс, сценарии проверки и ограничения](frontend/README.md).
- [Сервер, публичный API и подключение анализатора](backend/README.md).

На новом окружении для первого запуска добавьте `-Install`; рекомендуется Python 3.12. Frontend не требует Node.js или сборки. Остановка сервера — `Ctrl+C`.

**Режим `mock` возвращает синтетические ответы и не анализирует содержимое видео.** После реализации и проверки `analyzer.service.analyze_video` запускайте с `-Mode real`. Автоматической подмены реального анализа тестовым нет. Без параметра выбран режим `real`, который пока не готов к обработке видео.

На этапе 4 интерфейса выводятся общий результат и число событий. Подробный просмотр событий, таймкодов и кадров относится к этапу 5 интерфейса. Нумерация этапов интерфейса относится к его отдельному плану и не совпадает с этапами анализатора и интеграции ниже.

## Этапы анализатора и интеграции

1. **Локальный запуск.** Загрузить готовую модель на RTX 5070, проверить несколько видео, записать скорость, расход памяти и реальные ошибки. Дообучение на этом этапе не проводится.
2. **Наблюдения по видео.** Получать действия и состояния с временными отметками; проверять качество на разных сценах и ракурсах. Решение о дообучении принимать по измеренным ошибкам.
3. **Правила и доказательства.** Соединить наблюдения с условиями правил, проверить нормативные ссылки, выдавать возможное нарушение, время и настоящие кадры. Подготовить `analyze_video(video_path)` по согласованному контракту.
4. **Интеграция.** Соединить анализатор с интерфейсом и сервером, проверить путь от загрузки MOV до отчёта и публичный API с ключом.
5. **Проверка перед сдачей.** Оценить качество и временные отметки без смешивания дубликатов между частями выборки, проверить полный лимит времени, воспроизводимый запуск, подготовить демонстрацию и описать ограничения. Уже просмотренный открытый набор не является независимым скрытым тестом.

## Разделение работы

- Ергали и ассистент: анализатор видео, локальная модель, правила, нормативные ссылки, кадры-доказательства и проверка качества в `analyzer/`.
- Друг: весь интерфейс в `frontend/` и сервер приложения в `backend/` — загрузка, задания, статусы и API. Экран результатов тоже делает друг. Подробная задача: [docs/TEAMMATE_TASK.md](docs/TEAMMATE_TASK.md).
- Вместе: соединение частей, развёртывание и проверка на ноутбуке Ергали с RTX 5070.

## Совместная работа

Работаем в отдельных ветках без префикса `codex/`: `analyzer` для анализатора и `web-api` для интерфейса и сервера. После завершённого и проверенного этапа готовим отдельный PR. Изменения перед объединением просматриваем. Push и создание PR выполняет только Ергали; агенты готовят локальные изменения. Для отправки с его компьютера проверяется аккаунт `yergaliuly`. Друг передаёт подготовленные изменения Ергали без публикации агентом.

Единый формат обмена между частями записан в [docs/API_CONTRACT.md](docs/API_CONTRACT.md). Анализатор возвращает смысловой результат, сервер добавляет номер задания и статус. Интерфейс и сервер используют обозначенные тестовые ответы до подключения готового анализатора.

Код хранится в GitHub. Обработка видео выполняется на оборудовании, где запущен наш backend с локальной моделью. Наличие репозитория само по себе не запускает обработку и не публикует приложение.

Видео, таблица разметки, извлечённые кадры, веса моделей и секреты остаются вне Git. Локальные заметки по исходным видео находятся в исключённой из Git папке `review/`.
