# Forte Cash Audit

Проект команды KDvibers для кейса ForteBank: загрузка кассового видео, локальный анализ и результат с возможными нарушениями, временем события и подтверждающими кадрами.

Интерфейс и сервер соединены: выбор MOV автоматически запускает загрузку, ожидание и вывод результата. Экран результатов показывает события по времени, полные объяснения, кадры с увеличением и переходы в исходное видео. По сообщению Данияра, зависимости согласованы и настоящий анализ через интерфейс уже работает в его локальных изменениях. Эти изменения интеграции ещё не опубликованы и в этой копии не проверены; подготовка Funnel здесь выполняется в явно обозначенном тестовом режиме.

В сохранённых материалах этапа 1 модель запущена локально на RTX 5070 и проверена на видео. Скорость и расход памяти измерены; выявлены существенные ошибки понимания последовательности. Эти материалы не являются свежим протоколом ещё не опубликованной интеграции Данияра. Результаты и инструкция запуска: [analyzer/README.md](analyzer/README.md).

## Демонстрация и проверка приложения — этап 8

Рекомендуемый локальный запуск использует отдельное окружение `.venv-app`
и сохраняет рабочую `.venv` анализатора Данияра. На новом компьютере нужен
Python 3.12 x64; Node.js 22+ нужен только для автоматических frontend-тестов.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\demo.ps1 -Install
```

Откройте <http://127.0.0.1:8000>. Скрипт создаёт нейтральный образец,
запускает только `mock` на локальном адресе и использует отдельные данные
`backend/.local/demo`. События и кадры синтетические. Для повторного запуска
уберите `-Install`; остановка — Ctrl+C.

Полная проверка приложения: `scripts/check.ps1 -Install`; диагностика запуска:
`scripts/doctor.ps1`. Порядок подготовки нового компьютера, команды и показ
за 3–4 минуты — в [руководстве демонстрации](docs/DEMO_GUIDE.md).

## Публичный доступ: Tailscale Funnel и защита содержимого

**Мы выбрали Tailscale Funnel как основной способ предоставить публичный
интерфейс и API, сохранив расшифровку запросов на ноутбуке команды.**
В кейсе одновременно требуется внешний URL, локальное выполнение моделей
и ограничение передачи тестовых видео третьим лицам. Отдельного разъяснения
про зашифрованный транзит в предоставленном задании мы не нашли. Поэтому мы
сравнили способы публикации и выбрали схему, в которой внешнему ретранслятору
не требуется доступ к содержимому видео.

> **Граница защиты: TLS начинается в браузере или API-клиенте и завершается
> в Tailscale на ноутбуке, где запущено приложение. Серверы Funnel передают
> зашифрованный поток и не расшифровывают видео, API-ключ и кадры результата.**
> После расшифровки запрос передаётся нашему backend по HTTP через
> `127.0.0.1` внутри того же ноутбука. Это локальный участок, не пересылка
> открытого видео между ноутбуками или через интернет.

Такое устройство ретрансляции описано в
[официальной документации Tailscale](https://tailscale.com/kb/1223/funnel).
В прежней стандартной схеме Cloudflare Quick Tunnel внешнее TLS-соединение
завершалось на стороне Cloudflare. Именно место расшифровки, а не только
наличие значка HTTPS, стало причиной нашего выбора Funnel.

Мы отделяем сетевой доступ от вычислений: Funnel не распознаёт действия и
не вызывает модель вместо нашего приложения. В `real` обработка должна
выполняться локальным анализатором на ноутбуке Данияра после его интеграции.
Этот способ запуска проверен в **`mock` на нейтральных синтетических MOV**;
такие ответы не подтверждают качество реального анализа.

**Текущий статус проверки:** публичные DNS-записи появились после задержки.
HTTPS, API, загрузка и восстановление проверки прошли через внешний
ретранслятор Funnel с проверкой сертификата, без обхода по частному адресу
Tailscale. Нейтральный MOV размером 29 МБ прошёл полный тестовый путь за
107,49 с, включая 104,91 с приёма файла. Клиентом был ноутбук Касымбека.
Касымбек также подтвердил открытие сайта с пометкой «Тестовый режим»
с телефона через мобильный интернет без Tailscale/VPN. Загрузка видео
с телефона и полный `real` на ноутбуке Данияра ещё не проверены.
Этот замер не доказывает выполнение лимита 300 с настоящим анализатором.
Подробные результаты и оставшиеся проверки записаны в
[протоколе Funnel](docs/FUNNEL_ACCESS.md#протокол-этого-этапа).

**Мы не утверждаем, что сторонней инфраструктуры нет.** Зашифрованный поток
проходит через неё. Защита содержимого не равна сокрытию всех сетевых
метаданных, шифрованию файлов на диске или подтверждению отсутствия журналов
у провайдера. Наше техническое основание — отсутствие расшифровки на
ретрансляторе. Это выбранное командой решение при неполной конкретизации
правил; отдельного одобрения организаторов и гарантии их трактовки у нас нет.

### Запуск тестового режима

На компьютере заранее должны быть установлены Tailscale и Python 3.12 x64.
Владелец компьютера выполняет вход в Tailscale и разрешает Funnel для своего
устройства по инструкции. Затем из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\public-funnel.ps1 -Install
```

`-Install` устанавливает **только зависимости backend** в `.venv-app`;
Tailscale, вход в учётную запись и разрешения сети он не настраивает.
По умолчанию используются `mock`, `127.0.0.1:8020` и отдельные данные
`backend/.local/funnel-mock`. Дождитесь сообщения о готовности и текущего
HTTPS-адреса. Для повторного запуска уберите `-Install`; остановка — Ctrl+C.

Сначала Касымбек проверяет публикацию синтетического сценария на своём
ноутбуке. Данияр получает **код и инструкции**, запускает Funnel и приложение
на своём ноутбуке и после интеграции проверяет `real`. Итоговая ссылка жюри
должна вести именно на ноутбук Данияра: пересылка записей между участниками
в этой схеме не нужна.

Подготовка Tailscale, проверка API, остановка, ограничения и объяснение
защиты для жюри — в [руководстве Funnel](docs/FUNNEL_ACCESS.md).
Прежний вариант Cloudflare сохранён как
[справочный материал этапа 9](docs/PUBLIC_ACCESS.md); новый основной запуск
его не использует.

## Прямой запуск интерфейса и API

В этой копии версии Pillow в требованиях сервера и анализатора различаются. По сообщению Данияра, совместимые зависимости уже подобраны в его локальных изменениях. До их получения и проверки не устанавливайте требования backend из старой копии поверх его рабочего окружения; подробности текущей копии — в [analyzer/README.md](analyzer/README.md).

Из корня репозитория, в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\backend\start.ps1 -Mode mock
```

Откройте <http://127.0.0.1:8000>. Выберите или перетащите MOV: файл автоматически отправится на сервер, после чего появятся состояние проверки и итоговое заключение. Интерфейс и API работают в одном процессе, отдельный сервер frontend не нужен.

- [Интерфейс, сценарии проверки и ограничения](frontend/README.md).
- [Сервер, публичный API и подключение анализатора](backend/README.md).

На новом окружении для первого запуска добавьте `-Install`; рекомендуется Python 3.12. Frontend не требует Node.js или сборки. Остановка сервера — `Ctrl+C`.

Этот прямой запуск использует `.venv` и `backend/.local`. Для отдельной
демонстрационной среды используйте `scripts/demo.ps1` из раздела выше.

**Режим `mock` возвращает синтетические ответы и не анализирует содержимое видео.** После получения и проверки интеграции `analyzer.service.analyze_video` запускайте с `-Mode real`. Автоматической подмены реального анализа тестовым нет. У прямого `backend/start.ps1` без параметра выбран `real`; в этой копии его готовность не подтверждена.

На этапе 5 интерфейса доступны общий результат, отдельные события с таймкодами, полные объяснения и 1–3 кадра каждого события. Кадры можно увеличить, а таймкод — открыть в исходном видео, если его кодек поддерживается браузером. При неподдерживаемом кодеке события и кадры остаются доступны. Нумерация этапов интерфейса относится к его отдельному плану и не совпадает с этапами анализатора и интеграции ниже.

**Этап 6 интерфейса — подготовка к подключению анализатора.** Проверочный клиент поддерживает `--expect-mode real`, полную проверку результата с JPEG-кадрами и замер времени отправки и ожидания. Данияр сообщил об успешном локальном подключении; в общей копии нужно получить его изменения и повторить настоящий анализ через API и интерфейс, затем через Funnel. Порядок подключения описан в [backend/README.md](backend/README.md#подключение-анализатора-данияра).

**Этап 7 — восстановление проверки.** После обновления страницы или повторного открытия сайта восстанавливается последняя проверка в том же браузере. Запрашивается существующее задание, видео автоматически повторно не отправляется. Готовые события и кадры можно открыть без работающего анализатора; исходный файл для плеера выбирается повторно на компьютере. Истёкшая сессия и удалённый результат имеют отдельные сообщения. Подробности и сценарии проверки — в [frontend/README.md](frontend/README.md).

## Этапы анализатора и интеграции

1. **Локальный запуск.** Загрузить готовую модель на RTX 5070, проверить несколько видео, записать скорость, расход памяти и реальные ошибки. Дообучение на этом этапе не проводится.
2. **Наблюдения по видео.** Получать действия и состояния с временными отметками; проверять качество на разных сценах и ракурсах. Решение о дообучении принимать по измеренным ошибкам.
3. **Правила и доказательства.** Соединить наблюдения с условиями правил, проверить нормативные ссылки, выдавать возможное нарушение, время и настоящие кадры. Подготовить `analyze_video(video_path)` по согласованному контракту.
4. **Интеграция.** Соединить анализатор с интерфейсом и сервером, проверить путь от загрузки MOV до отчёта и публичный API с ключом.
5. **Проверка перед сдачей.** Оценить качество и временные отметки без смешивания дубликатов между частями выборки, проверить полный лимит времени, воспроизводимый запуск, подготовить демонстрацию и описать ограничения. Уже просмотренный открытый набор не является независимым скрытым тестом.

## Разделение работы

- Данияр: анализатор видео, локальная модель, правила, нормативные ссылки, кадры-доказательства и проверка качества в `analyzer/`.
- Касымбек: весь интерфейс в `frontend/` и сервер приложения в `backend/` — загрузка, задания, статусы, API и экран результатов. Подробная задача: [docs/TEAMMATE_TASK.md](docs/TEAMMATE_TASK.md).
- Вместе: соединение частей, развёртывание и проверка на ноутбуке Данияра с RTX 5070.

## Совместная работа

Данияр работает в ветке `analyzer`, Касымбек — в `web-api`. После завершённого и проверенного этапа готовим отдельный PR. Изменения перед объединением просматриваем. Каждый участник отправляет свою ветку и создаёт PR. Сохраняем настоящее авторство участников и не передаём друг другу учётные данные.

Единый формат обмена между частями записан в [docs/API_CONTRACT.md](docs/API_CONTRACT.md). Анализатор возвращает смысловой результат, сервер добавляет номер задания и статус. Интерфейс и сервер используют обозначенные тестовые ответы до подключения готового анализатора.

Код хранится в GitHub. Обработка видео выполняется на оборудовании, где запущен наш backend с локальной моделью. Наличие репозитория само по себе не запускает обработку и не публикует приложение.

Видео, таблица разметки, извлечённые кадры, веса моделей и секреты остаются вне Git. Локальные заметки по исходным видео находятся в исключённой из Git папке `review/`.
