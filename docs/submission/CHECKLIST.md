# Готовность к совместной проверке и сдаче

Исторический снимок таблицы и первоначальных условий: 17 октября 2026 года.
Он сохранён для истории и не описывает текущую готовность. Статус «проверено в mock» означает
проверку приложения с синтетическими ответами; он не подтверждает распознавание.
После изменения коммита, модели, правил или настроек повторяют затронутые
проверки и записывают новую версию в журнале.

**Обновление 18.10.2026:** `analyzer/service.py` подключён в real, зависимости
совместного окружения согласованы. Основной внешний пользовательский путь
подтверждён Данияром: загрузка, отчёт, кадры и сохранение после обновления.
44,988 с — серверное время, не полный клиентский срок. В рабочем профиле одно
условное правило. Окончательная версия после этапов 4–5, внешний API-замер,
новые видео и повторный запуск остаются предметом этапа 7. Актуальные факты,
включая неудачные попытки: [протокол интеграции](../FUNNEL_INTEGRATION_STATUS.md).
Сервис может быть остановлен на время доработок.

FAQ 13 и 23 требуют удалённый доступ по публичному URL. Раздел 7 требует
локального выполнения моделей и обработки без интернета после получения
весов. Покупка собственного домена в задании не требуется. Раздел 10 ограничивает
передачу тестовых видео третьим лицам. Текущий маршрут Funnel с расшифровкой
на ноутбуке команды и фактические внешние проверки описаны в
[протоколе интеграции](../FUNNEL_INTEGRATION_STATUS.md); прежний mock-прогон
не является доказательством качества настоящего анализа.

## Исторические условия первой интеграции

Список ниже сохранён как исходный: подключение анализатора, согласование
Pillow и настоящие локальные ответы уже подтверждены в текущем протоколе.
Лицензии рабочего состава описаны в [COMPONENTS.md](../COMPONENTS.md);
полная проверка транзитивных компонентов и окончательной версии ещё не завершена.

- [ ] Данияр передал коммит с `analyzer/service.py` и рабочим `analyze_video(video_path)`.
- [ ] Согласованы зависимости. Конфликт текущих Pillow 13.0.0 / 11.3.0 разрешён и проверен; рабочая среда не перезаписана вслепую.
- [ ] Зафиксированы модель, веса, версия runtime, параметры и команды запуска.
- [ ] Проверены лицензии финальных моделей, кода и используемых компонентов на соответствие условиям задания; источники записаны.
- [ ] Получен настоящий результат через локальный API с `--expect-mode real`.
- [ ] Данияр подтвердил содержание событий, источников и кадров; Касымбек подтвердил их отображение.

Доступность `/health` и `analyzer_ready=true` не доказывают точность или успешный
полный анализ. В текущей версии проверяются исполнитель и обе локальные модели
через `check_ready()`. Режим `real` не заменяется на `mock` при ошибке.

## Что записать по критериям оценки

| Критерий задания | Максимум | Нужные факты в итоговом материале |
| --- | ---: | --- |
| Качество обнаружения | 25 | Результаты по вердикту на видео: правильные ответы, ложные срабатывания, пропуски и технические сбои |
| Качество локализации | 15 | Таймкоды, соответствие кадров событию, ошибки времени относительно человеческого эталона |
| Качество классификации | 15 | Сопоставление типов с событиями; человеческая проверка типов, поскольку исходная разметка их не содержит |
| Обоснованность правил | 15 | Реальные источники РК и связь правила с видимыми фактами; отсутствие выдуманных пунктов |
| Устойчивость | 10 | Результаты на видео, не использованных для настройки, и другом ракурсе; ограничения малой выборки |
| Готовность продукта | 10 | Полный сценарий, несколько событий, понятные ошибки, восстановление и повторный запуск |
| Техническое решение | 10 | Обоснование архитектуры, локальность, воспроизводимость и измеренные ресурсы |

Сумма максимумов — 100. Таблица не является собственной оценкой баллов и не
позволяет обещать место: оценку выставляет жюри. Уже просмотренные видео нельзя
представлять как независимый скрытый тест; дубликаты держат в одной части выборки.

## Перед передачей реквизитов жюри

- [ ] Пройдены сценарии [совместной проверки](ACCEPTANCE.md); отказы описаны, а не исключены из отчёта.
- [ ] Заполнен [журнал замеров](MEASUREMENTS.template.md), включая версии и весь срок ответа. Неизмеренные поля обозначены «н/д», а не нулём.
- [ ] Приложение в `real`; финальная модель и правила соответствуют проверенному коммиту.
- [ ] Текущий URL проверен с другого устройства/сети; поддерживается автоматический API без интерактивного входа посредника.
- [ ] Согласован маршрут для видео жюри; временная ссылка не успеет смениться из-за перезапуска во время проверки.
- [ ] Ноутбук Данияра подключён к питанию и сети, сон и перезагрузки не прервут согласованное окно проверки.
- [ ] Файл MOV около 29 МБ принят в итоговой конфигурации; лимит времени проверен на реальном анализе.
- [ ] Ключ от текущего экземпляра передан отдельно; его нет в README, Git, примерах, скриншотах и открытых логах.
- [ ] В [материале для жюри](JURY_HANDOFF.template.md) нет незаполненных полей, неподтверждённых возможностей и результатов mock под видом real.
- [ ] В Git отсутствуют исходные видео, разметка, кадры, веса и заполненные журналы с данными.
- [ ] Команда знает, как остановить свой сервер, как повторно запустить его и куда сообщить изменившийся адрес.

Финальный статус фиксируют оба участника в локальной копии материала для жюри.
При незакрытом обязательном пункте указывают конкретный блокер и ответственного.
Подготовка документов сама по себе не переводит проект в состояние «готов к сдаче».
