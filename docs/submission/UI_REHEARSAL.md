# Практическая проверка интерфейса

Проверяем загрузку, ожидание, результаты и восстановление на нейтральном
синтетическом MOV. Реальный анализатор и записи банка в этом прогоне не используются.
Касымбек проверяет приложение; совместный внешний прогон на ноутбуке Данияра
выполняется по [плану приёмки](ACCEPTANCE.md). Локальный анализатор уже подключён.
Номер 11 ниже — историческое обозначение работы над приложением, а не новый
этап [общего плана из семи этапов](../PROJECT_PLAN.md).

После объединения Funnel 18.10.2026 прошли все 69 frontend-тестов, включая
сохранение ограниченного состава правил и понятные безопасные ошибки.
Это автоматические проверки, не подтверждение полной браузерной репетиции
или настоящего внешнего анализа. Таблица ниже сохраняет результаты предыдущего прогона.

Позднее 18.10.2026 Данияр подтвердил основной внешний real-сценарий: загрузку
правильного кассового видео, отчёт, кадры и их сохранение после обновления.
Серверное время 44,988 с не является полным клиентским замером. Подтверждение,
маршрут и оставшиеся проверки — в [протоколе интеграции](../FUNNEL_INTEGRATION_STATUS.md).
Исторические строки ниже не отменяют эту проверку. Полная матрица экранов,
клавиатуры и окончательной версии по-прежнему требует отдельной репетиции.

Для краткой ручной проверки использовался отдельный локальный сервер на
`http://127.0.0.1:8768`, режим `mock`, сценарий `multiple` с задержкой 20 секунд
и нейтральный `sample.mov` в изолированном каталоге
`backend/.local/stage11/manual-b245894186244361950fbf00cc23e58e/`.
Ответ `/health` перед передачей на проверку подтвердил `mode: mock` и
`analyzer_ready: true`. Этот временный запуск ограничен одним часом;
команды ниже позволяют повторить демонстрацию после его остановки.

HTTP-прогон подтвердил два события и четыре декодируемых JPEG для `multiple`,
пустой результат `no_violation` для `clean`, технический `failed` без вердикта
для `error`. Восстановление возвращает то же задание; повторные GET и повторный
POST с прежним UUID не создают дубликат. Без сессии получен 401, для чужого
задания — 404, без CSRF или с чужим Origin — 403, для неподдерживаемого
расширения — 415, для пустого и повреждённого MOV — 422. Отказы не создают
новых заданий. Подробный локальный журнал хранится в
`backend/.local/stage11/http-run-96ws2wu3/REPORT.md`; этот каталог исключён из Git.

Повторить штатную самопроверку в готовом окружении:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check.ps1
if ($LASTEXITCODE -ne 0) { throw 'Самопроверка не пройдена.' }
```

Если Node.js не добавлен в PATH, укажите `-NodePath` с полным путём к `node.exe`.
Одно предупреждение Starlette о будущем переходе тестового клиента с `httpx`
на `httpx2` не привело к сбою тестов; зависимости на этом этапе не менялись.

Изменения этапа:

- При потере связи пользователь видит понятное сообщение и кнопку повторного
  подключения. Инструкции запуска сервера остаются в документации команды.
- На ширине до 430 px верхняя панель допускает перенос элементов.
- Окно помощи учитывает меняющуюся высоту экрана телефона; сохранён запасной
  вариант для браузеров без поддержки `dvh`.
- Добавлены девять проверок: автоматическая единственная отправка, четыре
  варианта недопустимого файла, отказ повреждённого MOV, неполный результат,
  истечение ожидания и восстановление связи. Ошибки не становятся заключением
  «нарушений нет», запрос готового задания не отправляет видео заново.

## Репетиция на ноутбуке

После основного прогона получено дополнительное замечание: при недоступности
сервера верхняя строка сохраняла прежнее сообщение «Сервер готов», хотя карточка
уже сообщала об ошибке получения состояния. Повторная диагностика показала,
что порт 8768 не прослушивался; первоначальный временный запуск имел ограничение
в один час. Сервер повторно запущен с тем же каталогом данных обычной командой
запуска, без часового таймера. `/health` подтвердил готовность `mock`.

Из навигации убраны ссылка «Как это работает» и значок помощи слева. Верхняя
кнопка помощи и краткая последовательность действий внизу сохранены.
Сообщения о связи уточнены; автоматического повторного POST по-прежнему нет.
Все 54 frontend-теста прошли, включая обновление строки состояния при потере
связи и её восстановлении без повторной отправки файла. Эти последующие
изменения требуют отдельного подтверждения в браузере.

Выполняйте из корня репозитория. Сначала остановите ранее запущенную вами
локальную демоверсию через Ctrl+C в её окне, чтобы два сервера не использовали
одни данные `backend/.local/demo`. Чужие процессы не завершайте.

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\demo.ps1 -Port 8768 -Scenario multiple -DelaySeconds 15
```

После сообщения о готовности откройте <http://127.0.0.1:8768> в обычном браузере.
Тестовый файл: `backend/.local/demo/sample.mov`. Это 12-секундная цветная
тестовая запись без звука. На первом запуске окружения добавьте `-Install`.
Не открывайте `frontend/index.html` отдельным файлом: приложению нужен сервер.

Пройдите полную таблицу и отметьте отдельные результаты в своей локальной копии.
Общее сообщение об успешном кратком сценарии не заполняет автоматически все
пункты: ниже «Не зафиксировано отдельно» относится к расширенной проверке.
Фразы «должно работать» или «проверено по коду» не означают успешный браузерный тест.

| ID | Действия и ожидаемый результат | Фактический результат |
| --- | --- | --- |
| U1 | Выберите `sample.mov`. Загрузка начинается сразу, без дополнительной кнопки. Во время ожидания повторный выбор заблокирован, видны тестовый режим и номер задания. | Не зафиксировано отдельно |
| U2 | После сообщения о приёме файла запишите номер задания и нажмите F5. Восстанавливается тот же номер; в панели Network браузера нет нового POST `/ui/analyze`. | Не зафиксировано отдельно |
| U3 | Дождитесь отчёта: два события, три кадра у первого и один у второго. Переключение события меняет выделение, описание и кадры. Везде сохранена маркировка тестового режима. | Не зафиксировано отдельно |
| U4 | После F5 нажмите «Выбрать исходное видео» и выберите тот же файл. Нажмите таймкод `00:01.500`: плеер переходит к 1,5 секунды и остаётся на паузе. В Network не возникает новая отправка. | U5 | Увеличьте кадр, переключите соседние кнопками и стрелками клавиатуры. Нажмите Esc: окно закрывается, фокус возвращается к исходной миниатюре. | Не зафиксировано отдельно |
| U6 | Закройте вкладку и откройте тот же адрес в том же браузере. Отчёт восстанавливается. Отмена выбора исходного файла не удаляет события и кадры. | Не зафиксировано отдельно |
| U7 | Начните новую проверку. После приёма файла включите Offline во вкладке Network, дождитесь сообщения о связи, затем верните Online и запросите результат. Сохраняется номер задания, нового POST нет. | Не зафиксировано отдельно |
| U8 | Начните новую проверку и выберите неподдерживаемый файл, затем пустой или повреждённый MOV. Видна понятная ошибка, ложного вердикта нет. Затем корректный `sample.mov` снова принимается. | Не зафиксировано отдельно |

| U10 | Проверьте ширины 1366, 768, 390 и 320 px, затем масштаб 200%. Кнопки и сообщения читаются, горизонтальная прокрутка страницы не нужна. Проверьте длинное имя MOV, длинное описание события и шапку при ошибке связи. | Не зафиксировано отдельно |

Для U8 можно создать отдельные безопасные файлы внутри игнорируемого каталога:

```powershell
$fixtureDir = Join-Path (Get-Location).Path ('backend\.local\ui-fixtures-' + [Guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $fixtureDir -ErrorAction Stop | Out-Null
Set-Content -LiteralPath (Join-Path $fixtureDir 'unsupported.txt') -Value 'UI check only' -Encoding UTF8
Set-Content -LiteralPath (Join-Path $fixtureDir 'damaged.mov') -Value 'This is not a video' -Encoding UTF8
[IO.File]::WriteAllBytes((Join-Path $fixtureDir 'empty.mov'), [byte[]]@())
Write-Output $fixtureDir
```

Если диалог выбора скрывает неподдерживаемый формат, перетащите файл на область
загрузки. Для теста связи при начальном открытии остановите только свой сервер,
перезагрузите страницу, проверьте сообщение и затем снова запустите его:
«Подключиться снова» должно вернуть возможность выбора видео.

Отдельно выполните сценарии ниже: сначала Ctrl+C предыдущего сервера, затем
одна команда и **новая** проверка на странице. Старый восстановленный отчёт
не меняется при смене тестового сценария.

```powershell
# Сначала выполнить и завершить этот запуск.
powershell -ExecutionPolicy Bypass -File .\scripts\demo.ps1 -Port 8768 -Scenario clean -DelaySeconds 2
# После Ctrl+C выполнить второй запуск.
powershell -ExecutionPolicy Bypass -File .\scripts\demo.ps1 -Port 8768 -Scenario error -DelaySeconds 2
```

- `clean`: сообщение об отсутствии нарушений, пустой список событий.
- `error`: техническая ошибка, возможность новой проверки, итогового вердикта нет.

## Телефон и внешняя ссылка

Используйте текущую ссылку собственного тестового сервера из
[инструкции Funnel](../FUNNEL_ACCESS.md). Если он остановлен,
запустите `scripts/public-funnel.ps1` в тестовом режиме и дождитесь готовности.
Проверьте напечатанный адрес. Передайте на телефон только нейтральный `sample.mov`.

1. На телефоне отключите Wi-Fi и откройте текущую HTTPS-ссылку через мобильную сеть.
2. Выберите нейтральный MOV, дождитесь двух синтетических событий, откройте кадр.
3. Обновите страницу: отчёт должен восстановиться в том же браузере.
4. Проверьте портретную и горизонтальную ориентацию; кнопки окна помощи и кадра
   должны оставаться доступны при открытых панелях браузера.
5. Запишите модель телефона, браузер, дату и результат. Поддержка кодека MOV
   отмечается отдельно от успешной загрузки и отображения отчёта.

Полная матрица этого синтетического теста отдельно не запротоколирована.
Раннее подтверждение Касымбека касалось открытия страницы. Позднее Данияр
подтвердил внешний real-сценарий с загрузкой, отчётом, кадрами и восстановлением;
он описан в текущем протоколе выше. Это не проверка всех ориентаций и браузеров.
Записи организаторов не используйте для этого прогона.

## Когда репетиция пройдена

Сохраните заполненную копию в `backend/.local/submission/` или `review/evaluation/`.
В ней должны быть коммит, браузер, размеры экрана, исход каждого сценария и
описание оставшихся ошибок. Не добавляйте ключи, реальные записи и кадры в Git.
В репозитории допускается общий итог синтетического прогона без этих материалов.

Только после U1–U10, отдельных `clean`/`error` и проверки с телефона можно
отметить браузерную репетицию завершённой. Затем остаётся совместная проверка
`real` по [ACCEPTANCE.md](ACCEPTANCE.md), включая реальные кадры и измерение времени.
