## Как использовать интерфейс

1. Открыть указанный адрес и дождаться готовности сервера.
2. Выбрать или перетащить `.mov`. Передача начинается автоматически.
3. Дождаться окончания обработки и открыть события с объяснениями и кадрами.
4. Нажать таймкод для перехода в исходное видео, если браузер поддерживает
   его кодек. После обновления страницы для плеера потребуется повторно
   выбрать исходный файл локально; это не новый анализ.

Результат служит подсказкой для проверки человеком. Он сообщает о визуальных
признаках возможного нарушения, а не об окончательном юридическом заключении.

## API

Оба маршрута требуют `X-API-Key`. Без правильного ключа — HTTP 401.
API не требует браузерной авторизации.

| Запрос | Тело | Ответ |
| --- | --- | --- |
| `POST /api/v1/analyze` | `multipart/form-data`, поле `file`, файл `.mov` | JSON с `job_id` |
| `GET /api/v1/jobs/{job_id}` | Без тела | JSON со статусом `processing`, `done` или `failed` |

Формы ответов ниже иллюстрируют контракт, это не результаты тестовых видео:

```json
{"job_id":"example-job"}
```

```json
{"job_id":"example-job","status":"processing"}
```

```json
{"job_id":"example-job","status":"done","verdict":"no_violation","violations":[]}
```

При `done` и `verdict="violation"` массив `violations` содержит события.
У события есть `type`, `timecode_sec`, `description` и `evidence_frames`.
У каждого из 1–3 кадров — `timestamp_sec` и `image_base64`: JPEG в Base64
без `data:`. Объяснение и нормативный источник находятся в `description`.

```json
{"job_id":"example-job","status":"failed"}
```

У `failed` нет вердикта; это технический сбой. Неизвестное или удалённое
задание — HTTP 404. При 429 очередь или ограничение частоты требуют ожидания
с учётом `Retry-After`; 503 означает неготовность сервиса. Повторная отправка
при неопределённом сетевом результате не должна происходить автоматически.

Пример полного запроса и опроса существующим клиентом из корня репозитория
в PowerShell; ключ читается из локального файла и не печатается:

```powershell
$apiUrl = Read-Host 'Базовый HTTPS адрес API'
$keyFile = Read-Host 'Путь к файлу отдельно полученного API-ключа'
$videoFile = Read-Host 'Путь к разрешённому MOV для проверки'
.\.venv-app\Scripts\python.exe -m backend.check_api --base-url $apiUrl --expect-mode real --key-file $keyFile --video $videoFile
```

Команда требует подготовленного окружения приложения. До отправки видео
проверяют допустимость выбранного сетевого маршрута. Подробная схема и
установка: [ЗАПОЛНИТЬ: ссылки на docs/API_CONTRACT.md и инструкции в проверенном коммите].
