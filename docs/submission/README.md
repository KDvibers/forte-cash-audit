# Пакет сдачи и совместная проверка

Касымбек отвечает за интерфейс и сервер приложения, Данияр — за анализатор,
правила и доказательства. Этот пакет связывает подготовленные части проекта
с требованиями сдачи кейса ForteBank.

**Состояние на 18 октября 2026 года: приложение соединено с настоящим
локальным анализатором; финальная приёмка ещё не завершена.** Модуль
`analyzer/service.py` существует и используется в `real`. Проверены настоящие
ответы, очередь и отдельные загрузки через публичный ретранслятор Funnel.
Условия, успешные прогоны и отказы сохраняются в
[протоколе интеграции](../FUNNEL_INTEGRATION_STATUS.md); этот пакет не является
заявлением о полной готовности или точности на видео жюри.

Сохраняются [семь этапов проекта](../PROJECT_PLAN.md): 1–2 выполнены, 3–5
частичны. Основной путь этапа 6 подтверждён внешней загрузкой, отчётом, кадрами
и восстановлением после обновления для текущего профиля. Окончательная версия,
полный внешний API-замер и остальные проверки этапа 7 ещё предстоят.
Сейчас включено одно условное правило о деньгах на столе после исчезновения
человека из рабочей зоны. Остальные действия и другой ракурс требуют проверки.

1. Прочитайте текущий протокол интеграции и создайте локальные копии шаблонов.
2. Повторите на окончательной версии подтверждённый сценарий с независимого
   устройства: загрузка, ожидание, отчёт, кадры и восстановление после обновления.
   В предыдущей пользовательской проверке измерены 44,988 с на сервере,
   а не полный клиентский срок. Во время доработок сервис может быть остановлен.
3. Запишите фактический режим, маршрут, полный срок и содержание результата.
   Сохраняйте неуспешные попытки; проверка транспорта не измеряет качество модели.
4. Перед сдачей проверьте окончательную версию, заполните материал для жюри,
   сверив его с работающим сервисом. Ключ передайте отдельно; ноутбук и сервер
   должны оставаться включёнными.

В остальных материалах пакета могут сохраняться исторические номера внутренних
проверок. Они не добавляют этапы к общему плану. Чек-лист, сценарии и заполненный
пакет ещё предстоит сверить при финальном аудите; пустые шаблоны остаются шаблонами.

## Запуск и проверка

Из корня подготовленного проекта, когда приложение и его Funnel остановлены:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\real.ps1 -StartModels -CheckOnly
powershell -ExecutionPolicy Bypass -File .\scripts\funnel-real.ps1 -CheckOnly
powershell -ExecutionPolicy Bypass -File .\scripts\funnel-real.ps1
```

При ошибке диагностики не переходите к следующей команде. Модели работают
локально на 8080 и 8081, приложение — на 8020. Ключ этого запуска хранится
в `backend/.local/funnel-real/api-key.txt`; значение не добавляется в документы.
Остановка — Ctrl+C в терминале Funnel. Порядок проверки и восстановления
после 503/таймаута: [REAL_RUNBOOK.md](../REAL_RUNBOOK.md).

На независимом клиенте без Tailscale/VPN, с подготовленными зависимостями
проверки и приватно полученным файлом ключа:

```powershell
$url = Read-Host 'Текущий HTTPS-адрес сервиса'
$keyFile = Read-Host 'Путь к локальному файлу API-ключа'
$video = Read-Host 'Путь к разрешённому MOV с ожидаемым событием'
powershell -ExecutionPolicy Bypass -File .\scripts\check-real.ps1 `
    -BaseUrl $url -KeyFile $keyFile -Video $video -RequireEvents
```

Это явный `real`-тест с клиентским пределом 300 секунд. Для нормального
контрольного видео уберите `-RequireEvents`; отрицательный результат относится
только к включённому правилу. Автоматическая проверка JSON/JPEG не заменяет
просмотр события и сравнение кадров с оригиналом. Локальная самопроверка кода
запускается `scripts/check.ps1`; её временный mock-прогон не проверяет модель.

Дедлайн, указанный командой: **18 октября 2026, 12:00, Asia/Qyzylorda (UTC+5)**.
Часовой пояс в исходном документе отдельно не указан; уточнение организаторов
имеет приоритет. Это ориентир планирования, а не подтверждение готовности.

## Где хранить заполненные материалы

В Git остаются инструкции, пустые шаблоны и обезличенные итоги проверок. Личные
адреса сервиса, разметку, подробные результаты и кадры храните в исключённых локальных
каталогах. Ключ API передаётся отдельно закрытым способом и не вставляется
даже в заполненный текст отчёта.

Из корня репозитория в PowerShell создайте новый каталог для заполнения:

```powershell
$packetName = 'draft-' + [Guid]::NewGuid().ToString('N')
$packetDir = Join-Path (Get-Location).Path ('backend\.local\submission\' + $packetName)
New-Item -ItemType Directory -Path $packetDir -ErrorAction Stop | Out-Null
Copy-Item -LiteralPath '.\docs\submission\JURY_HANDOFF.template.md' -Destination (Join-Path $packetDir 'JURY_HANDOFF.md')
Copy-Item -LiteralPath '.\docs\submission\MEASUREMENTS.template.md' -Destination (Join-Path $packetDir 'MEASUREMENTS.md')
Write-Output $packetDir
```

Каждый запуск создаёт новую папку и не заменяет заполненные материалы.
Ссылки на инструкции и примеры команд открывайте в исходном репозитории;
пустой шаблон сам по себе не является готовым пакетом для отправки.

## Что уже проверено и что предстоит

Настоящий анализ с одним правилом проверялся локально и через публичный
ретранслятор Funnel. Два одновременных коротких запроса проверили очередь
по частному маршруту Tailscale. Отдельный короткий публичный прогон занял
53,422 с; длинный после смены подключения — 251,265 с. До успешного длинного
прогона были два отказа. Публичные IP в этих тестах выбирались внутри клиента
на том же ноутбуке: это не полный сценарий с независимого устройства.

Обычная страница открылась на телефоне. Полная загрузка и результат на телефоне,
устойчивый внешний API-путь, повторный запуск окончательной версии, перезагрузка
Windows и проверка новых видео остаются предметом приёмки. Текущую готовность
после исправлений нужно проверять заново; исторический замер её не гарантирует.
Подробности и последующие результаты — в [протоколе](../FUNNEL_INTEGRATION_STATUS.md).
