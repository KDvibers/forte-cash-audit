# Запуск и восстановление real-сервиса

Для подготовленного ноутбука: веса и `.venv-app` уже установлены, вход в Tailscale выполнен. Приложение использует порт 8020; локальные модели 2B и 4B — 8080 и 8081. Запускается один экземпляр приложения. Если сервис уже работает и принимает задания, повторный запуск не нужен.

Окружение `.venv-app` зависит от базовой установки Python: её путь указан в
`.venv-app/pyvenv.cfg`. Сохраняйте эту установку вместе с локальными моделями;
копирование одной папки проекта на другой компьютер не создаёт рабочую среду.
На другом компьютере окружение нужно создать заново по закреплённым зависимостям.
Полная проверка после перезагрузки ОС и при отключённом интернете пока не проведена.

## Запуск

В PowerShell из корня проекта, когда приложение и его Funnel остановлены:

```powershell
Set-Location -LiteralPath 'C:\Daniyar\MyProjects\DatathonNU'
powershell -ExecutionPolicy Bypass -File .\scripts\real.ps1 -Port 8020 -StartModels -CheckOnly
powershell -ExecutionPolicy Bypass -File .\scripts\funnel-real.ps1 -CheckOnly
powershell -ExecutionPolicy Bypass -File .\scripts\funnel-real.ps1
```

Первый вызов запускает только отсутствующие серверы моделей и проверяет их роли; приложение не запускается. Уже занятые порты не освобождаются. Второй вызов проверяет готовность к публикации. При ошибке остановитесь и разберите сообщение; не переходите к следующей команде. Рабочее окружение переустанавливать не требуется.

Последняя команда запускает сайт/API и Funnel на этом ноутбуке. Оставьте терминал открытым и возьмите HTTPS-адрес из его вывода. При уже действующей публикации `-CheckOnly` может отказать: сначала штатно остановите принадлежащий этому запуску терминал, а не сбрасывайте настройки Tailscale.

Проверка состояния по адресу из вывода:

```powershell
$url = Read-Host 'Текущий HTTPS-адрес Funnel'
Invoke-RestMethod -Uri ($url.TrimEnd('/') + '/health') -TimeoutSec 10
```

Нужны одновременно `status=ok`, `mode=real`, `analyzer_ready=true`. Один HTTP 200 недостаточен. `mock` возвращает синтетические ответы; он не подходит для настоящей проверки видео. При неисправности real автоматически в mock не переключается. Проверка с ноутбука, подключённого к Tailscale, может идти по частному маршруту и не доказывает публичный доступ.

Данные этого запуска: `backend/.local/funnel-real/`; ключ API: `backend/.local/funnel-real/api-key.txt`. Ключ не выводить в журнал, не добавлять в Git или код сайта; передавать проверяющему приватно. У отдельного локального `scripts/real.ps1` другое хранилище — `backend/.local/real/`.

## Проверка с телефона и восстановление страницы

1. На телефоне выключить Wi-Fi, Tailscale и VPN, оставить мобильную сеть. Открыть текущую ссылку и убедиться, что нет пометки «Тестовый режим».
2. Выбрать разрешённый MOV. Измерить время от начала отправки до готового отчёта; проверить событие, таймкод, ссылку на источник и настоящие кадры.
3. После принятия загрузки обновить страницу: должно восстановиться то же задание без повторной отправки. Для плеера после обновления может потребоваться повторно выбрать тот же файл локально; это не новая загрузка.
4. При кратком обрыве связи восстановить сеть и существующее задание. Не нажимать повторную загрузку, пока не проверен его статус. Ошибка связи или `failed` не означают отсутствие нарушений.

Данияр подтвердил внешний real-сценарий: правильное кассовое видео загружено, отчёт и кадры видны и сохраняются после обновления. Сервер зафиксировал 44,988 с; полный клиентский срок не измерен. После изменений этапов 4–5 повторить сценарий на окончательной версии с полным замером. Подтверждение и границы проверки — в [протоколе интеграции](FUNNEL_INTEGRATION_STATUS.md). Во время доработок сервис может быть остановлен.

## Остановка и ошибки

**Остановка:** Ctrl+C в терминале Funnel, затем дождаться завершения. Остановятся своё приложение и своя публикация; модели останутся загруженными. Ключ и готовые результаты сохраняются до штатной очистки по сроку хранения. Незавершённые задания после перезапуска получают `failed` и сами повторно не запускаются.

Срок хранения завершённого задания и его загрузки в текущей конфигурации —
24 часа после завершения. Перезапуск этот срок не продлевает. API-ключ штатная
очистка заданий не удаляет.

**503 / неготовность после таймаута:** новые задания не отправлять. Защитная блокировка не позволяет начать следующий анализ поверх запроса, который мог остаться выполняться в модели. Перед перезапуском проверить обе модели и занятость их слотов:

```powershell
Invoke-RestMethod http://127.0.0.1:8080/health -TimeoutSec 5
Invoke-RestMethod http://127.0.0.1:8081/health -TimeoutSec 5
foreach ($modelPort in 8080, 8081) {
    foreach ($slot in (Invoke-RestMethod "http://127.0.0.1:$modelPort/slots" -TimeoutSec 5)) {
        $slot | Select-Object @{Name='port'; Expression={$modelPort}}, id, is_processing
    }
}
```

Оба `/health` должны отвечать `status=ok`, все слоты — `is_processing=false`. Здоровье модели само по себе не означает, что она свободна. Если запрос ещё выполняется, дождаться его завершения и повторить проверку; если модель зависла или статус неизвестен, сначала разобраться с её собственным процессом и журналом, не запускать второй экземпляр поверх занятого порта. Журналы: `runs/model-server/` и `runs/model-server-8081/`.

После подтверждения простоя остановить приложение через Ctrl+C и повторить команды запуска. Отсутствующие модели запустит `-StartModels`; зависший процесс эта команда не заменяет. Проверить real/готовность и повторить один известный сценарий. Визуально недостаточный, но технически завершённый анализ может вернуть `failed` без блокировки следующих заданий; ориентироваться на сообщение и `/health`, не подменять его отрицательным вердиктом.

**Ссылка не открывается:** проверить сеть и `tailscale funnel status`. Если имя не находится, это DNS, а не ошибка модели. Не выполнять общий `reset`, `down` или выход из аккаунта ради обычного восстановления; повторная публикация может продлить проблему DNS. Не отключать проверку TLS. **429:** дождаться свободного места в очереди. **Неподходящий/повреждённый файл:** выбрать корректный MOV, не ожидать заключения по отклонённому файлу.

Точные измерения, неуспешные попытки и оставшиеся проверки: [FUNNEL_INTEGRATION_STATUS.md](FUNNEL_INTEGRATION_STATUS.md). Запуск после полной перезагрузки Windows пока не проверен. Успешный запуск не подтверждает качество на новых видео и выполнение 300 секунд для любой загрузки; сейчас включено одно условное правило.
