# Публичный доступ через Tailscale Funnel

Актуальные команды настоящего запуска, передача без потери локальных
изменений Данияра и внешний тест ≤300 секунд собраны в
[REAL_FUNNEL_HANDOFF.md](REAL_FUNNEL_HANDOFF.md). Приведённые ниже успешные
измерения относятся к прошлому тестовому запуску, а не к real-приёмке.

Мы подготовили отдельный способ запуска приложения через Funnel. Основной
сценарий этого этапа — **`mock` на ноутбуке Касымбека с синтетическим MOV**.
Настоящий анализатор уже подключён локально; финальный внешний запуск через
Funnel на ноутбуке Данияра проверяется отдельно. Новый запуск не использует `cloudflared`.

> **Зафиксированная проверка Касымбека: HTTP-проверки через публичный ретранслятор Funnel прошли
> в `mock`, включая загрузку нейтрального MOV размером 29 МБ.** Проверка
> выполнялась с ноутбука Касымбека с подтверждённым публичным маршрутом.
> Касымбек подтвердил открытие сайта с пометкой «Тестовый режим» с телефона
> через мобильный интернет без Tailscale/VPN. Загрузка с телефона и полный
> внешний анализ в `real` через Funnel ещё не подтверждены. Подробности и измерения — в протоколе ниже.

## Почему мы выбрали этот маршрут

В кейсе есть три требования, которые мы рассматривали вместе: публичный URL
для удалённой проверки, локальное выполнение AI и запрет передачи тестовых
видео третьим лицам. Правила не уточняют отдельно случай зашифрованного
транзита без доступа посредника к содержимому. Мы выбрали архитектуру,
которая сохраняет публичный доступ и переносит точку расшифровки на наше
оборудование.

> **Содержимое запросов защищено TLS между клиентом и ноутбуком команды.
> Ретранслятор Funnel пересылает зашифрованные данные, не расшифровывая их.
> TLS завершается в Tailscale на том же ноутбуке, где работает наш backend.**
> Это относится к загрузке видео, API-ключу в заголовке, запросам состояния
> и возвращаемым кадрам. Основание — описанная поставщиком архитектура,
> а не наш собственный аудит инфраструктуры Tailscale.

[Официальное описание прохождения запроса и ответа](https://tailscale.com/kb/1223/funnel).

Путь окончательного запуска:

```text
Браузер / API-клиент жюри
    │ HTTPS: содержимое запроса зашифровано
    ▼
Ретранслятор Funnel — передача потока без расшифровки содержимого
    │ TLS-соединение клиента продолжается до ноутбука
    ▼
Tailscale на ноутбуке Данияра — завершение TLS
    │ HTTP на 127.0.0.1:8020, внутри того же ноутбука
    ▼
Backend: приём MOV → локальное задание → локальный анализатор → результат
```

Ответ возвращается тем же маршрутом: локальный backend передаёт его Tailscale,
а через интернет он идёт в защищённом соединении к клиенту. Публичный порт
этого запуска — 443; 8020 является внутренним портом нашего приложения.

Мы используем Funnel только для сетевой передачи. Это не облачный анализатор
и не замена модели. В финальном `real` модель должна работать локально;
отсутствие внешних AI-вызовов проверяется при интеграции анализатора.
Наличие Funnel само по себе не подтверждает устройство ещё не подключённой
модели.

### Что эта защита означает и чего она не означает

| Утверждение | Как мы его описываем |
| --- | --- |
| Посредник получает расшифрованное видео | В выбранной схеме ретранслятор Funnel не завершает клиентский TLS и не читает содержимое. |
| Данные вообще не проходят через чужие серверы | Неверно: через них проходит зашифрованный поток. |
| «Funnel шифрует всё» | Слишком широко: описываем защиту сетевого содержимого до ноутбука, не всех метаданных и файлов на диске. |
| Backend получает расшифрованный запрос | Да, по loopback внутри того же компьютера; этот HTTP-участок не направляется в интернет. |
| Локальные видео и база зашифрованы этой функцией | Нет: Funnel не заменяет защиту диска и учётной записи Windows. |
| Провайдер не видит никаких метаданных и ничего не журналирует | Мы это не проверяли и не заявляем. |
| Организаторы согласовали этот маршрут | Подтверждения нет. Мы подробно раскрываем выбранную архитектуру и её границы. |

Мы считаем отсутствие доступа ретранслятора к содержимому существенной
мерой конфиденциальности. Но техническая мера сама по себе не определяет
трактовку слов «передача третьим лицам» в условиях кейса. Наша документация
не подменяет правила утверждением о гарантированном соответствии. До
финальной сдачи команда фиксирует фактический маршрут, режим и ограничения
в [материале для жюри](submission/JURY_HANDOFF.template.md).

## 1. Подготовить Tailscale на нужном ноутбуке

Нужны Windows, Python 3.12 x64 и доступ в интернет. Установите официальный
[клиент Tailscale для Windows](https://tailscale.com/kb/1022/install-windows),
затем владелец ноутбука входит в свою учётную запись. Пароли, коды входа
и ключи регистрации устройств не передаются через репозиторий.

В PowerShell проверьте:

```powershell
tailscale version
tailscale status
tailscale funnel status --json
tailscale serve status --json
```

Если команда не найдена после установки, откройте новое окно PowerShell
или используйте полный путь к `tailscale.exe` в каталоге установки.
Для Funnel в сети Tailscale должны быть разрешены MagicDNS, HTTPS
и соответствующая возможность для устройства. Владелец сети выполняет
предлагаемую клиентом настройку; скрипт проекта сам не меняет эти разрешения.

Перед первым запуском приложения конфигурация Serve/Funnel на устройстве
должна быть пустой. Если там есть другой сервис, наш запуск остановится,
чтобы не заменить его публикацию. Изучите существующий сервис и согласуйте
его остановку с владельцем. Не выполняйте общий `reset` ради нашего запуска.

Если разрешение Funnel ещё не включено, выполните вручную:

```powershell
tailscale funnel --https=443 http://127.0.0.1:8020
```

Перейдите по официальной ссылке настройки, которую выдаст клиент, и завершите
настройку в своей учётной записи. Затем завершите эту подготовительную
команду Ctrl+C и проверьте, что её публикация снята. На данном шаге backend
ещё не запущен: успешный ответ приложения не ожидается. Далее приложение
и публикацией управляет единый скрипт проекта.

Funnel открывает сервис публичным посетителям; обычный Serve ограничивает
доступ сетью Tailscale. Жюри не должно устанавливать Tailscale, вступать
в нашу сеть или входить в нашу учётную запись.

## 2. Запустить mock из корня репозитория

Первая установка зависимостей приложения и запуск:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\public-funnel.ps1 -Install
```

Повторный запуск:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\public-funnel.ps1
```

Параметр `-Install` устанавливает только backend в `.venv-app`. Он не
устанавливает Tailscale, не выполняет вход и не разрешает Funnel вместо
владельца сети. Рабочее окружение анализатора `.venv` не изменяется.
Если нужен конкретный Python, передайте `-PythonPath` с полным путём
к Python 3.12 x64.

По умолчанию выбран `mock`, сценарий `multiple` с двумя синтетическими
событиями, задержка 2 секунды и внутренний адрес `127.0.0.1:8020`.
Другой локальный порт можно указать через `-Port`; чужой процесс на занятом
порту скрипт не завершает. Одновременно на устройстве запускайте одну
публикацию этого приложения.

Для наглядного ожидания используйте `-DelaySeconds 15`, для другого
синтетического исхода — `-Scenario clean`, `one` или `error`. Параметр
`-TailscalePath` принимает полный путь к уже установленному официальному
`tailscale.exe`, а `-VenvPath` — подготовленное окружение приложения.
Предел файла в этом запуске — 100 МиБ; это ограничение нашего backend,
не обещание пропускной способности Funnel.

Скрипт получает HTTPS-имя устройства из Tailscale, проверяет адрес и передаёт
его backend как единственный публичный origin. Дождитесь сообщения
о готовности. Только после этого открывайте напечатанный URL. Для внешнего
доступа используйте этот URL, а не внутренний HTTP-адрес опубликованного
экземпляра: его проверки рассчитаны на согласованный HTTPS-origin.

| Режим | Локальные данные | Файл ключа |
| --- | --- | --- |
| `mock` | `backend/.local/funnel-mock` | `backend/.local/funnel-mock/api-key.txt` |
| `real` | `backend/.local/funnel-real` | `backend/.local/funnel-real/api-key.txt` |

Эти каталоги исключены из Git. Образец `sample.mov` в `funnel-mock` содержит
только синтетическую сцену. Ключ текущего экземпляра не совпадает обязательно
с ключом локального `demo` или прежнего запуска Cloudflare.

Новый запуск сохраняет проверки Host, HTTPS, Origin/CSRF и браузерную
изоляцию заданий. Публичные API-маршруты требуют `X-API-Key`. Браузеру общий
API-ключ не выдаётся. Интерфейс с загрузкой при этом публичен: знание ссылки
позволяет начать собственную проверку, а cookie и CSRF не являются входом
по паролю. Публикуется приложение целиком, не отдельный сервер модели.

## 3. Проверить HTTPS, загрузку и восстановление

Не закрывая окно запуска, откройте второе окно PowerShell в корне репозитория:

```powershell
$publicUrl = Read-Host 'HTTPS-адрес текущего Funnel'
powershell -ExecutionPolicy Bypass -File .\scripts\check-public.ps1 `
    -BaseUrl $publicUrl `
    -ExpectMode mock `
    -KeyFile .\backend\.local\funnel-mock\api-key.txt `
    -VenvPath .venv-app
```

Проверка использует нейтральные видео и проверяет публичный API, браузерные
HTTP-маршруты, cookie, CSRF и результат с JPEG. Ключ читается из файла,
не включается в команду и не печатается. Этот прогон не является визуальной
проверкой интерфейса или оценкой качества модели.

**На компьютере с активным Tailscale тот же HTTPS-адрес может разрешаться
в частный адрес `100.x` и обходить публичный ретранслятор.** Поэтому успешный
`check-public.ps1` на ноутбуке команды подтверждает приложение по выбранному
маршруту, но не доступ жюри из интернета. Фиксируйте используемый адрес и
обязательно выполняйте отдельный прогон без Tailscale с другого устройства.
Сообщение клиента `Funnel on` также само по себе не заменяет эту проверку.

С другого устройства и другой сети, без активного Tailscale-подключения:

1. Откройте HTTPS-адрес и убедитесь, что виден тестовый режим.
2. Загрузите нейтральный MOV; дождитесь двух синтетических событий.
3. Откройте увеличенный кадр и перейдите к таймкоду исходного видео.
4. Нажмите F5: должна восстановиться та же проверка, без повторной отправки.
5. Начните новую проверку тем же файлом и дождитесь отдельного результата.

Отдельно измерьте передачу MOV около 29 МБ. Запишите время от начала загрузки
до `job_id`, затем ожидание и получение полного ответа с кадрами. Складывайте
весь путь при проверке лимита 300 секунд: внутренний таймаут задания 285
секунд отсчитывается с входа запроса в сервер, но не охватывает весь путь
до него и обратную передачу ответа. Прежние замеры Cloudflare не являются
замерами Funnel. Ограничение пропускной способности сервиса требует проверки
на фактическом подключении; успех маленького образца не доказывает скорость
передачи большого видео.

## 4. Остановить и запустить повторно

Нажмите **Ctrl+C** в окне `public-funnel.ps1` и дождитесь завершения.
Скрипт управляет собственным процессом публикации и собственным backend;
службу Tailscale и другие процессы он не выключает. После остановки проверьте:

```powershell
tailscale funnel status --json
tailscale serve status --json
```

Публикация нашего приложения должна исчезнуть. При сообщении об ошибке
остановки сначала изучите состояние; не выполняйте `reset`, `logout`
или отключение всей службы для очистки одного сервиса.

Используется запуск без `--bg`: постоянную фоновую публикацию и автозапуск
после перезагрузки этот скрипт не создаёт. После перезагрузки запустите
его снова и повторите проверку. Принцип работы флага и команды состояния:
[справочник CLI Funnel](https://tailscale.com/kb/1311/tailscale-funnel).

Имя устройства связано с настройкой Tailscale. При переносе на другой
ноутбук фактический адрес нужно получить и проверить заново. Cookie и
браузерное хранилище привязаны к origin: готовый отчёт не переносится
автоматически на адрес другого ноутбука.

## 5. Передать запуск Данияру

Касымбек передаёт через GitHub код и эту инструкцию. Видео, база заданий,
API-ключи, токены Tailscale и локальные сертификаты в репозиторий не попадают.
Данияр устанавливает и настраивает Tailscale на своём ноутбуке самостоятельно,
получает код и сначала повторяет `mock`-проверку.

В переданном Данияром документе `INTEGRATION.md` сообщается о работающем
локальном анализе через сайт и API. Его изменения интеграции ещё не
опубликованы и не проверены в данной копии. При объединении сохраняем
изменения Данияра в приложении, результатах, исполнителе, конфигурации и
файлах зависимостей: **нельзя заменять их целиком старыми файлами этой ветки**.
Добавляем запуск Funnel к согласованной интеграции и проверяем совмещение.

В документе Данияра описаны:

- Совместное окружение `.venv-app` с Pillow 11.3.0 и PyAV 16.0.1.
  Исследовательская `.venv` остаётся отдельно.
- Скрипт `scripts/real.ps1`: `-Install` устанавливает совместные зависимости,
  `-StartModels` поднимает отсутствующие модельные серверы, `-CheckOnly`
  проверяет готовность без запуска приложения.
- Локальные модельные серверы 2B на 8080 и 4B на 8081. Эти порты не
  публикуются через Funnel; внешнему клиенту нужен только backend.

Скрипт `scripts/real.ps1` сохранён в объединённой версии. На ноутбуке Данияра
с уже подготовленным окружением порядок такой:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\real.ps1 -StartModels -CheckOnly
powershell -ExecutionPolicy Bypass -File .\scripts\funnel-real.ps1 -CheckOnly
powershell -ExecutionPolicy Bypass -File .\scripts\funnel-real.ps1
```

Публикацию выполняйте только после успешных проверок моделей и приложения.
Если зависимости уже подготовлены, установка не нужна. Для новой среды Funnel
используйте отдельный отсутствующий каталог, например
`scripts/funnel-real.ps1 -Install -VenvPath .venv-real`. У этого скрипта
`-Install` запрещён с существующей средой и несовместим с `-CheckOnly`;
после установки во всех командах сохраняйте тот же `-VenvPath`, без `-Install`.

**Одновременно работает только один backend с исполнителем анализа.**
Если локальное приложение уже запущено через `real.ps1`, сначала остановите
именно его штатным Ctrl+C. По инструкции Данияра модельные серверы после
этого остаются загруженными. `-StartModels -CheckOnly` готовит модели,
а `public-funnel.ps1 -Mode real` становится единственным приложением,
использующим GPU. Два полных запуска `real.ps1` и Funnel параллельно
не допускаются, даже если у них разные порты и каталоги данных.

Текущая интеграция проверяет один сигнал: наличные видны на столе после
исчезновения человека из наблюдаемой рабочей зоны. Это не готовое
распознавание всех видов нарушений. В историческом протоколе интеграции приведены локальные
полные API-замеры 48,02, 80,52 и 247,33 секунды на знакомых роликах.
Они включают loopback-передачу, но **не измеряют Funnel или интернет жюри**;
здесь они не являются повторно выполненным прогоном. Последующие изменения
правила и локальные замеры описаны в [STAGE45_STATUS.md](STAGE45_STATUS.md).
Успешный полный `real` через Funnel ещё требуется подтвердить отдельно.

При ошибке модели реальный режим должен сообщать об ошибке, а не выдавать
тестовые ответы. В `/health` проверяются и код HTTP, и `mode`, `status`,
`analyzer_ready`; импорт функции анализатора не заменяет пробный полный
анализ. После успешной проверки жюри передаётся URL **ноутбука Данияра**.

**Расшифровка и анализ настоящего видео происходят на ноутбуке Данияра.
Ноутбук Касымбека не является промежуточным сервером.** Тестовый запуск
у Касымбека нужен для подготовки кода и проверки маршрута; пересылка
загруженных жюри записей между участниками не предусмотрена.

Ноутбук с опубликованным приложением должен оставаться включённым, с питанием
и интернетом. Сон и выключение прерывают доступ. Публичный URL не превращает
ноутбук в постоянно доступный удалённый сервер.

## Если запуск не работает

| Сообщение или симптом | Действие |
| --- | --- |
| Tailscale отсутствует или вход не выполнен | Установить официальный клиент и войти на этом ноутбуке; `-Install` это не делает. |
| Funnel не разрешён | Владелец сети завершает настройку HTTPS и Funnel по подсказке клиента. |
| Уже настроены Serve/Funnel | Разобраться с существующей публикацией; наш скрипт её не заменяет. |
| Локальный порт 8020 занят | Остановить свой предыдущий запуск или выбрать свободный `-Port`. |
| API отвечает 401 | Проверить файл ключа именно `funnel-mock` или `funnel-real` текущего запуска. |
| Ошибка Host/Origin/HTTPS | Проверить URL текущего запуска и конфигурацию прокси; не отключать защитные проверки. |
| На ноутбуке работает, на телефоне без Tailscale — «сервер не найден» | Проверить публичное DNS-разрешение и внешний маршрут; локальный адрес `100.x` подтверждает только частный доступ. |
| Результат не появляется | Проверить режим и готовность `/health`, состояние задания и вывод `check-public.ps1`. |
| Адрес не работает после перезагрузки | Запустить скрипт и проверить публикацию снова; автозапуск не настроен. |
| На сайте показаны синтетические события | Это `mock`. Публикация URL не включает настоящий анализатор автоматически. |

В трекере Tailscale описан сбой регистрации Funnel: частная сеть продолжает
работать, хотя публичный доступ нарушен. Для некоторых случаев помогает
перезапуск клиента. Это возможная диагностическая гипотеза для нашего
случая, **не установленная причина и не гарантия исправления**:
[обсуждение #21114](https://github.com/tailscale/tailscale/issues/21114).
После штатной остановки нашего приложения владелец Windows может один раз
перезапустить службу из PowerShell с правами администратора:

```powershell
Restart-Service -Name Tailscale
```

Это временно прерывает все соединения Tailscale на ноутбуке. После восстановления
связи снова запустите `public-funnel.ps1` и проверьте телефон вне Tailscale.
Не заменяйте эту диагностику общим `reset` или переименованием устройства:
это меняет конфигурацию, а в трекере есть отдельные сообщения о проблемах
DNS после смены имени — [обсуждение #21156](https://github.com/tailscale/tailscale/issues/21156).
Если внешний доступ не восстановился, зафиксируйте результат и продолжайте
диагностику DNS/регистрации; повторные зелёные проверки по частному адресу
не закрывают проблему.

В публичном прогоне тестовый клиент направлял соединения точного имени
приложения на полученный из публичного DNS адрес ретранслятора. Записаны
24 HTTPS-соединения по этому маршруту; отдельно проверены фактический
удалённый IP и успешный ответ `/health`. Исходные hostname, SNI и Host
сохранялись, проверка сертификата не отключалась. Выбор адреса изменялся
только внутри процесса проверочного клиента; файл hosts и постоянные
DNS-настройки Windows не изменялись. Явный HTTP-прокси не использовался.

Это подтверждает прохождение запросов через **публичный ретранслятор**,
а не скрытый переход по адресу `100.x`. Автоматический клиент работал на том же
ноутбуке. Отдельно Касымбек подтвердил открытие страницы по обычному HTTPS-имени
с телефона через мобильный интернет без Tailscale/VPN. Это ручное подтверждение
внешней доступности страницы; полный сценарий загрузки и просмотра результатов
на телефоне ещё не пройден.
При итоговом запуске требуется проверка по обычному HTTPS-имени без
принудительного выбора IP. Адреса ретранслятора могут меняться;
не закрепляйте их в настройках приложения или в файле hosts.

Наблюдаемая задержка появления публичных DNS-записей составила около
14 минут 32 секунд после указанного запуска. Это результат одного случая,
а не обещание срока распространения DNS. Он не позволяет отделить эффект
перезапуска от изменения состояния или распространения записей у сервиса.

**107,49 секунды — время тестового режима, не реального анализатора.**
Одна передача заняла 104,91 секунды и уже расходует общий бюджет 300 секунд.
После переноса на ноутбук Данияра нужен новый замер от начала загрузки
до получения полного настоящего результата. Исторические локальные 247,33 секунды
для длинного видео приведены в разделе интеграции отдельно; последующие улучшения
описаны в [STAGE45_STATUS.md](STAGE45_STATUS.md). Нельзя складывать
или сравнивать замеры разных видео и сетей как готовое доказательство
соблюдения общего лимита. Текущий этап подтверждает транспорт и контракт
в `mock`; финальная доступность и производительность `real` ещё проверяются.

результатами; наличие инструкции и зелёный `mock` не заменяют итоговый `real`.
