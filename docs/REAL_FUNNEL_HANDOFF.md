## 3. Точные команды запуска

Когда модели уже запущены Данияром, из корня проекта:

```powershell
Set-Location -LiteralPath 'C:\Daniyar\MyProjects\DatathonNU'
powershell -ExecutionPolicy Bypass -File .\scripts\funnel-real.ps1 -CheckOnly
```

`-CheckOnly` проверяет зависимости, контракт анализатора и оба сервера
моделей, но не загружает видео и не публикует сайт. Если есть `[FAIL]`,
сначала устранить причину; переключение на mock не является исправлением.

После успешной диагностики **точная команда настоящего запуска**:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\funnel-real.ps1
```

Скрипт использует `.venv-app`; ничего в неё не устанавливает. Дождаться
готовности и HTTPS-адреса **ноутбука Данияра**. Адрес ноутбука Касымбека
нельзя использовать как итоговый адрес настоящего анализатора.

Если модели ещё не работают, их запуск выполняет Данияр после освобождения
GPU. По опубликованному скрипту это две отдельные команды в двух терминалах:

```powershell
powershell -ExecutionPolicy Bypass -File .\analyzer\start_model.ps1 -ModelSize 2b -Port 8080 -ContextSize 2048
```

```powershell
powershell -ExecutionPolicy Bypass -File .\analyzer\start_model.ps1 -ModelSize 4b -Port 8081 -ContextSize 4096
```

Если его согласованный `scripts/real.ps1 -StartModels -CheckOnly` уже
поднял эти модели, второй раз их не запускать. Остановить локальный
web-сервер перед Funnel: два приложения не должны одновременно обращаться
к GPU. Блокировка real защищает разные каталоги данных **одной копии
репозитория**; другой checkout, ручные исследования или внешние клиенты
моделей этой блокировкой не управляются.

Для совершенно новой среды, только при необходимости:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\funnel-real.ps1 -Install -VenvPath .venv-real
```

Эта команда создаёт среду, проверяет готовность и затем пробует запустить
публикацию. Если модели не готовы, публикация не начнётся. `-CheckOnly`
не совместим с `-Install`: диагностика сама никогда не устанавливает пакеты.
`-Install` в real откажется работать с уже существующим каталогом среды.
Это защищает рабочие зависимости Данияра. После создания `.venv-real`
использовать тот же `-VenvPath .venv-real` во всех командах, без `-Install`.
Сначала объединить requirements обеих сторон; не удалять рабочую среду
ради повторного выполнения установки.

## 4. Остановка и повторный запуск

Нажать **Ctrl+C в терминале Funnel** и дождаться завершения. Скрипт
останавливает свой backend и свою публикацию, но не серверы моделей.
При повторном запуске использовать ту же команду и каталог данных:
ключ и завершённые результаты сохранятся до очистки по сроку хранения.
Незавершённое задание после остановки/перезапуска станет `failed`;
оно не запускается повторно автоматически.

Не выполнять общий `tailscale reset`, `down` или выход из аккаунта ради
обычного перезапуска. Если скрипт сообщил, что осталась публикация,
проверить `tailscale funnel status`, владельца процесса и порт 8020.
Чужую активную конфигурацию не сбрасывать.

После аварии или таймаута real-анализатора сервер прекращает запуск
новых заданий. Причина: прерванный Python-клиент не гарантирует остановку
вычисления внутри отдельного сервера модели. Оператор проверяет и при
необходимости перезапускает модели, затем приложение; не начинает новое
задание поверх незавершённого GPU-вызова.

Отдельный случай — недостаточно визуальных данных после полностью завершённого
анализа. Только `IncompleteAnalysisError` самого анализатора с явным признаком
`inference_completed=True` оставляет возможность обработать следующее задание:
текущее получает `failed` без вердикта. Этот признак не ставится при неполном
проходе, исчерпании бюджета или технической ошибке. Остальные сбои блокируют
новые вызовы до проверки и перезапуска; одно название исключения без признака
завершения недостаточно.

## 5. Контракт, очередь и лимит времени

Рабочий режим строго `real`. Невозможность импортировать модуль, отсутствие
параметра `budget_sec`, ошибка `check_ready()` или явное `False` означают
неготовность. Если backend уже работает, в этом состоянии загрузка получает 503, `/health` показывает
`mode=real`, `analyzer_ready=false`, `status=degraded`; HTTP 200 у health
сам по себе не означает готовность. Новый launcher при неуспешном preflight
останавливается до публикации — доступного внешнего API ещё не будет.
Автоматического fallback на mock нет.

В исходном базовом коммите анализатор имел старую одноаргументную функцию.
Объединённая локальная версия поддерживает
`analyze_video(video_path: str, *, budget_sec: float = 260.0)` и `check_ready()`.
Старая версия без именованного бюджета по-прежнему отклоняется. Диагностика
Funnel дополнительно требует сведения об обеих локальных моделях от
`check_ready()` и доступность двух модельных `/health`; это не тест качества.

- Всего принимаются два незавершённых запроса, включая загрузки. Один
  анализ выполняется, второй может ждать. Третий получает 429 до чтения MOV.
- Внутренний срок по умолчанию — 285 секунд от входа запроса в ASGI,
  включая multipart, проверку файла, очередь и анализ.
- Перед вызовом модели передаётся `budget_sec = min(260, остаток - 5)`.
  Если осталось 15 секунд или меньше, новый анализ не начинается.
- Это не гарантия клиентских 300 секунд: DNS, начало соединения,
  путь до сервера и обратная передача результата расходуют дополнительное
  время. Клиентский тест меряет их вместе с загрузкой и очередью.
- Очередь не увеличивает бюджет. Два длинных видео могут не уложиться;
  такой тест нельзя объявлять успешным, даже если одиночный прошёл.

В публичном API остаются только `processing`, `done`, `failed` и
согласованная схема результата. Во внутреннем UI при `failed` добавлен
безопасный код ошибки: понятное сообщение о сроке, недоступности моделей
или перезапуске. Исключения, пути файлов и секреты не отправляются в UI.

## 6. Внешний тест настоящего результата

Использовать другой компьютер через другую сеть **без Tailscale/VPN**.
Проверка с сервера или клиента в той же tailnet может пойти по частному
маршруту и не подтверждает внешний Funnel. Клиенту нужна копия кода и
зависимостей проверки; модели на клиенте не запускаются.

На клиенте ключ хранится в локальном файле вне Git. Передать его жюри
или проверяющему приватно; браузер сайта этот общий ключ не получает.
Переменные ниже заполняются интерактивно, без сохранения секретного значения
в командной строке:

```powershell
$url = Read-Host 'HTTPS-адрес Funnel ноутбука Данияра'
$keyFile = Read-Host 'Полный путь к локальному файлу API-ключа'
$video = Read-Host 'Полный путь к разрешённому MOV с известным событием'
powershell -ExecutionPolicy Bypass -File .\scripts\check-real.ps1 `
    -BaseUrl $url -KeyFile $keyFile -Video $video -RequireEvents
```

Проверяется готовность real, 401 при отсутствующем/неверном ключе,
Origin/CSRF, затем POST → job_id → GET processing/done → JSON, таймкоды и
декодирование JPEG. Лимит каждой отправки **300 секунд от начала POST до
получения и проверки полного результата**, включая загрузку и очередь.
Поздний `done` не считается успехом. Предварительная диагностика и проверка
восстановления после готового результата измеряются отдельно.

Для ролика без ожидаемых событий убрать `-RequireEvents`. Это допустимый
отрицательный сценарий, но он не проверяет цепочку кадров. Для положительного
ролика обязателен успешный `-RequireEvents`, затем ручное сравнение кадров и
таймкодов с исходным видео. Корректный JPEG не доказывает его подлинность или
правильность распознавания.

Повторить через браузерные маршруты:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check-real.ps1 `
    -BaseUrl $url -KeyFile $keyFile -Video $video -Channel ui -RequireEvents
```

Здесь используется сессия с cookie и CSRF; после `done` выполняется
GET-восстановление по upload_id без повторного POST. Это проверка протокола,
а не замена ручного обновления страницы. Отчёт автоматически сохраняется
в `backend/.local/check-real/*.json`: тайминги, job_id, SHA256 и количества;
без ключей, путей видео, кадров и текстов результатов. Не добавлять отчёты в Git.

## 7. Две одновременные загрузки

Освободить GPU от исследований и остальных приложений. Выбрать два коротких
разрешённых видео, затем отдельно повторить с более длинными:

```powershell
$secondVideo = Read-Host 'Полный путь ко второму MOV'
powershell -ExecutionPolicy Bypass -File .\scripts\check-real.ps1 `
    -BaseUrl $url -KeyFile $keyFile -Video $video -SecondVideo $secondVideo `
    -Report backend/.local/check-real/two-real.json
```

Имя отчёта должно быть новым: существующие отчёты не перезаписываются.
Обе отправки начинаются одновременно и имеют независимые 300 секунд.
Успех — **оба** результата настоящие, корректные и своевременные.
После этого перенести только этот локальный метаотчёт на ноутбук Данияра,
в `backend/.local/check-real/`, и сопоставить с его базой:

```powershell
.\.venv-app\Scripts\python.exe -m backend.check_queue `
    --database backend/.local/funnel-real/jobs.sqlite3 `
    --report backend/.local/check-real/two-real.json
```

Проверка читает только метаданные в режиме read-only. Подтверждает два
успешных real-задания, пересечение времени запросов и отсутствие пересечения
интервалов исполнителя. Время до анализа включает приём файла и очередь;
отдельное ожидание GPU здесь не измеряется. Не менять системное время
во время теста. Проверку одного активного GPU-вызова дополнительно
сопоставить с локальными журналами моделей; сторонних клиентов быть не должно.

## 8. Телефон, обновление страницы и ошибки

1. На телефоне выключить Wi-Fi и Tailscale/VPN, использовать мобильную сеть.
2. Открыть новый HTTPS-адрес Данияра. Сайт показывает реальный режим и
   готовность, а не «Тестовый режим».
3. Выбрать разрешённый MOV. Записать время от выбора/начала отправки до
   готового отчёта. Во время ожидания обновить страницу: возвращается то же
   задание, повторной отправки нет.
4. Открыть событие, увеличить настоящий кадр, проверить таймкод и источник.
   После обновления браузер не хранит File: для плеера может понадобиться
   повторно выбрать **тот же файл локально**, без повторной загрузки.
5. Отключить мобильный интернет на несколько секунд и включить: понятная
   ошибка связи, затем GET-восстановление. Сетевая ошибка не равна failed
   анализа и не означает отсутствие нарушений.
6. Отдельно проверить повреждённый/неверный файл: понятная ошибка, без
   создания нормального заключения. При 429 дождаться свободного слота.
7. При свободном GPU остановить модели штатно и проверить health/загрузку:
   ошибка/503, никаких mock-результатов. После восстановления моделей
   перезапустить приложение и повторить положительный real-прогон.

Origin/CSRF защищают от чужого сайта, но не являются входом в аккаунт.
Сам сайт при Funnel публичный: любой посетитель может получить свою сессию
и загрузить файл в пределах лимитов. API жюри отдельно требует X-API-Key;
чужие браузерные результаты недоступны другой сессии.
