# Подготовка и демонстрация Forte Audit

Касымбек отвечает за приложение и API, Данияр — за анализатор. Этот порядок
позволяет проверить приложение на новом Windows-ноутбуке и провести показ
за 3–4 минуты. Все команды выполняются из корня репозитория в PowerShell 5.1
или новее.

**Демонстрация работает в `mock`: события и кадры синтетические и не описывают
содержимое загруженного видео.** Она проверяет загрузку, очередь, интерфейс,
восстановление и обработку ошибок. Настоящий анализ запускается через
`scripts/real.ps1`; порядок соединения и протокол проверок приведены в
[руководстве интеграции](INTEGRATION.md). Успешный синтетический показ
не подтверждает качество анализа видео.

Номера разделов ниже — порядок подготовки демонстрации. Они не заменяют
семь этапов [общего плана проекта](PROJECT_PLAN.md); интеграция относится
к этапу 6, итоговая проверка — к этапу 7.

## 1. Получить код и подготовить компьютер

Нужны Git и Python 3.12 x64. Для автоматических frontend-проверок дополнительно
нужен Node.js 22 или новее; для открытия сайта и самой демонстрации Node.js
не требуется. Веса модели и NVIDIA GPU для тестового показа не нужны.

На новом компьютере:

```powershell
git clone https://github.com/KDvibers/forte-cash-audit.git
Set-Location .\forte-cash-audit
```

Если репозиторий уже есть, откройте его каталог, проверьте `git status --short`
и обновите нужную ветку через `git pull --ff-only`. Локальные изменения сначала
сохраните обычным рабочим порядком. Для ещё не объединённого PR используйте
его ветку; после объединения — актуальный `main`. Учётные данные участников
не передаются между компьютерами.

## 2. Установить зависимости и выполнить проверки

Для полной проверки перед показом:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check.ps1 -Install
```

Скрипт создаёт отдельное окружение `.venv-app`, устанавливает зависимости
приложения и тестов, запускает pytest и Node-тесты. Затем проверяет API
через настоящий локальный HTTP-сервер на автоматически выбранном свободном
порту: синтетический MOV, ключ, режим и полный результат с JPEG-кадрами.
Временный сервер проверки останавливается после работы. Браузер, исходные
видео банка, веса и внешние сервисы анализа для этой проверки не нужны.

Если Python или Node.js не найдены, передайте пути к установленным программам.
Например, в этом варианте пути вводятся вручную:

```powershell
$pythonExe = Read-Host 'Полный путь к установленному python.exe'
$nodeExe = Read-Host 'Полный путь к установленному node.exe'
powershell -ExecutionPolicy Bypass -File .\scripts\check.ps1 -Install -PythonPath $pythonExe -NodePath $nodeExe
```

Первичная установка требует доступа к источникам Python-пакетов. После
установки автоматические проверки и тестовая демонстрация выполняются локально.
Для повторного запуска проверок `-Install` не нужен.

Окружение `.venv-app` отделено от `.venv` анализатора Данияра. Обе части
закрепляют Pillow 11.3.0. Для настоящего анализа дополнительно нужен
`av==16.0.1`; весь набор устанавливает `scripts/real.ps1 -Install` по
`backend/requirements-real.txt`. Команды этого руководства готовят
синтетический показ и не устанавливают веса модели. Не используйте
`-VenvPath .venv` поверх рабочего исследовательского окружения. При
необходимости выберите другое отдельное окружение через `-VenvPath`
и передавайте тот же путь всем скриптам запуска и проверки.

## 3. Проверить готовность и запустить показ

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\doctor.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\demo.ps1
```

`doctor.ps1` ничего не устанавливает. Он помогает проверить окружение и условия
запуска. По умолчанию выбран режим `mock`, порт 8000 и окружение `.venv-app`.

`demo.ps1` запускает интерфейс и API только на локальном адресе и только в `mock`.
По умолчанию выбран сценарий `multiple` с двумя событиями и задержкой анализа
15 секунд, чтобы успеть показать ожидание и восстановление страницы.

Откройте вручную <http://127.0.0.1:8000>. Браузер автоматически не запускается.
Для проверки выберите нейтральное видео `backend/.local/demo/sample.mov`.
Каталог `backend/.local/demo` содержит отдельные данные демонстрации: образец,
ключ, базу заданий и принятые файлы. Это локальные данные, их не добавляют в Git.

Чтобы остановить сервер, нажмите **Ctrl+C** в его окне и дождитесь возвращения
приглашения PowerShell. Остановка закрывает демонстрационный запуск; старые
задания и результаты сохраняются по правилам сервера.

Для быстрого показа без полного набора тестов можно сразу выполнить:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\demo.ps1 -Install
```

Это устанавливает зависимости приложения и запускает показ; выполнение
автоматических тестов такой командой не подтверждается.

## Показ за 3–4 минуты

| Время | Что делаем | Что объясняем |
| --- | --- | --- |
| 0:00–0:30 | Открываем страницу, показываем отметку тестового режима. | Сейчас демонстрируем работу приложения. Ответы синтетические; это не оценка качества модели. |
| 0:30–1:10 | Выбираем `sample.mov`, наблюдаем передачу и ожидание. После подтверждения приёма нажимаем F5. | Загрузка начинается автоматически. После F5 приложение запрашивает то же задание, а не отправляет видео заново. |
| 1:10–2:10 | Открываем два события, полное объяснение, увеличиваем кадр и переключаем соседние кадры. | У события и каждого кадра есть таймкод. Текст и изображения этого сценария созданы для проверки интерфейса. |
| 2:10–3:00 | Нажимаем «Выбрать исходное видео», выбираем тот же `sample.mov`, затем нажимаем таймкод. | После F5 браузеру нужен исходный файл для плеера. Повторный локальный выбор не создаёт задание и не отправляет файл. Воспроизведение запускается вручную. |
| 3:00–4:00 | Закрываем вкладку и открываем тот же адрес, либо показываем один из дополнительных сценариев ниже. | Готовый результат восстанавливается в той же браузерной сессии. Ошибка обработки отличается от результата без нарушений. |

При восстановлении используйте тот же браузер и адрес, включая порт.
`localhost` и `127.0.0.1` — разные адреса для браузерного хранилища.
После повторного открытия исходного файла сверяются имя, размер и известная
дата изменения; это не проверка совпадения содержимого файла.

## Дополнительные сценарии

Сначала остановите текущий демонстрационный сервер через Ctrl+C. Затем запустите
нужный сценарий:

```powershell
# Нет событий: успешный результат без нарушений.
powershell -ExecutionPolicy Bypass -File .\scripts\demo.ps1 -Scenario clean -DelaySeconds 2

# Техническая ошибка: заключение по видео не сформировано.
powershell -ExecutionPolicy Bypass -File .\scripts\demo.ps1 -Scenario error -DelaySeconds 2
```

Это два отдельных запуска: второй выполняется после остановки первого.
После перезапуска сайт может восстановить прежний отчёт. Нажмите
«Проверить другое видео» и загрузите образец, чтобы создать задание в новом
сценарии. `-Scenario one` возвращает одно тестовое событие, `multiple` — два.

## Если запуск не получился

| Ситуация | Что проверить |
| --- | --- |
| Нет окружения или Python-пакетов | Выполните `check.ps1 -Install` либо `demo.ps1 -Install`. Если Python не найден, передайте `-PythonPath` с действительным путём к Python 3.12 x64. |
| Node.js не найден или его версия ниже 22 | Для тестов нужен Node.js 22+. Передайте `-NodePath` скрипту `check.ps1` или установите подходящую версию. Сама демонстрация Node.js не использует. |
| Порт 8000 занят | Не останавливайте чужой процесс. Используйте `doctor.ps1 -Port 8001`, затем `demo.ps1 -Port 8001` и откройте `http://127.0.0.1:8001`. |
| Версия Pillow не соответствует требованиям | Обе части используют Pillow 11.3.0. Проверьте выбор `.venv-app` и установите закреплённые требования. Исследовательскую `.venv` Данияра не изменяйте. |
| Настоящий анализатор не готов | `analyzer/service.py` уже реализован. Для настоящего режима используйте `real.ps1 -Install -CheckOnly`, при необходимости с `-StartModels`: нужны PyAV и обе локальные модели. Диагностика не заменяет анализ через API. Синтетическая демонстрация остаётся отдельным режимом `mock`. |
| MOV не открывается в плеере | Поддержка зависит от кодека и браузера. Используйте нейтральный образец для показа плеера; события и JPEG-кадры доступны независимо от воспроизведения. |
| После F5 отчёт не восстановился | Убедитесь, что открыт тот же адрес и порт, cookie не удалены, хранилище браузера разрешено, а срок хранения результата не истёк. |
| Первый запуск без интернета не устанавливает пакеты | Установите зависимости заранее при доступе к источникам пакетов. Успешный локальный запуск приложения не требует копирования весов модели. |

## После синтетической демонстрации

1. **Проверить интеграцию этапа 6:** использовать реализованный
   `analyzer/service.py`, подготовить `.venv-app` через `scripts/real.ps1`
   и проверить настоящий MOV через API с `--expect-mode real` и через
   интерфейс. Команды и фактический протокол — в [INTEGRATION.md](INTEGRATION.md).
2. **Оценить реальное качество и время:** проверить события, нормативные ссылки,
   происхождение кадров и таймкоды на видео, измерить полный срок обработки,
   повторные задания и поведение при сбоях. Скорость диагностического запуска
   модели и успешные тесты приложения не заменяют эти измерения.
3. **Подготовить доступ и финальную сдачу:** обеспечить согласованный внешний
   доступ к приложению и API, проверить его с другого устройства, подготовить
   итоговую демонстрацию, ограничения и материалы по требованиям организаторов.

Демонстрационный запуск слушает только этот компьютер и не публикует сайт.
Готовность инфраструктуры приложения не означает завершённость анализа
нарушений и не гарантирует оценку жюри.
