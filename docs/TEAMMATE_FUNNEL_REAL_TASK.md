# Касымбеку: подготовка настоящего запуска через Funnel

Данияр завершает анализатор, временные правила и доказательства. Касымбек отвечает за весь интерфейс, экран результатов, сервер приложения и Funnel. Репозиторий общий; push и PR выполняет Данияр.

## Что подготовить параллельно

1. Подготовить точную команду запуска режима `real` на ноутбуке Данияра, список необходимых настроек и команды остановки и повторного запуска. Не использовать автоматический переход в `mock`, если модели или анализатор недоступны.
2. Проверить совместимость с `analyzer.service.analyze_video(video_path, budget_sec=...)`. Анализатор получает локальный путь к сохранённому видео и оставшееся время. На GPU работает один исполнитель. Не перезаписывать локальные изменения Данияра при переносе запуска из GitHub.
3. Подготовить внешний сценарий проверки: телефон в другой сети → HTTPS-страница → загрузка → обработка настоящим анализатором → результат → открытие JPEG и таймкодов. Первый финальный прогон делаем на RTX 5070 Данияра после освобождения GPU.
4. Проверить оба обязательных API-маршрута с ключом, неверный ключ, восстановление задания после обновления страницы, ошибки неподдерживаемого файла и недоступной модели. Ключ не должен попадать в браузерную сборку или Git.
5. Записать полный замер: начало передачи файла, окончание загрузки, ожидание очереди, анализ, получение результата. Проверяем лимит 300 секунд на всём пути. Время режима `mock` и время только локального анализатора не подтверждают этот лимит.
6. Проверить два одновременных запроса: один GPU-исполнитель, понятное ожидание, корректный оставшийся бюджет. Истёкшее время нельзя превращать в успешный ответ «нарушений нет».
7. Проверить остановку и повторный запуск приложения и публикации, доступ с телефона без Tailscale/VPN, работу с актуальной ссылкой Funnel.

## Что прислать Данияру

- SHA коммита, содержащего готовый запуск.
- Точную команду запуска, названия обязательных переменных и местоположение локальной конфигурации без значений секретов.
- Список проверенного в `real`, результаты замеров и оставшиеся препятствия. Явно отделить прежние проверки `mock`.
- Удобный момент для совместного внешнего прогона на ноутбуке Данияра.

## Совместимость результата

Поля API остаются прежними. `timecode_sec` первого правила теперь указывает первый кадр с сочетанием признаков, подтверждённый следующим кадром. Момент подтверждения и ограничения описываются в тексте. Несколько фрагментов с одной историей присутствия группируются в один сигнал. Экран должен показывать все события из ответа и реальные доказательные кадры.

`no_violation` относится только к перечисленным включённым проверкам; объём берётся из `describe_scope()`. `IncompleteAnalysisError` означает незавершённую проверку и переводится в `failed`, без подстановки пустого успешного результата.

Видео, извлечённые кадры, результаты с изображениями, веса и секреты остаются вне Git. Вычисления моделей выполняются локально. В описании публикации сохраняем фактическую архитектуру Funnel: TLS завершается на устройстве команды, ретранслятор передаёт зашифрованный поток. Техническая проверка этой схемы не заменяет отсутствующее подтверждение организаторов по трактовке условий кейса.
