# Внешний доступ к Forte Audit — этап 9

> **Предыдущий вариант: Cloudflare Quick Tunnel.** Основной способ внешнего
> доступа теперь описан в [руководстве Tailscale Funnel](FUNNEL_ACCESS.md)
> и запускается через `scripts/public-funnel.ps1`. Этот документ оставлен
> для воспроизведения прежних проверок. Команды `public.ps1` ниже по-прежнему
> запускают Cloudflare; они не переключают приложение на Funnel. Приведённые
> здесь замеры относятся только к прежнему маршруту, а не к новой публикации.

Одна HTTPS-ссылка открывает интерфейс и публичный API приложения, работающего
на ноутбуке Данияра. Для временной демонстрации используется Cloudflare Quick
Tunnel: покупать домен и регистрировать аккаунт не требуется. Ссылка действует,
пока запущены приложение и туннель; после нового запуска адрес меняется.
[Условия Quick Tunnel](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

В FAQ 13 кейса указано, что видео загружает жюри удалённо по ссылке команды;
FAQ 23 требует публичный URL. Раздел 7 отдельно требует локального выполнения
моделей и запрещает облачные AI-сервисы при обработке видео. Внешний доступ
и локальное выполнение анализатора — разные части решения.

**На этом этапе проверяем внешний доступ в `mock`: события и кадры
синтетические, содержимое видео не анализируется.** Реальный анализатор Данияра
подключается и проверяется отдельно.

## Что проходит через внешний сервис

Браузер или API-клиент соединяется по HTTPS с Cloudflare. Cloudflare завершает
внешнее TLS-соединение и передаёт HTTP-запросы через зашифрованный туннель
на приложение. Поэтому загружаемое видео и возвращаемые кадры проходят через
стороннюю инфраструктуру. Сам анализ выполняется на ноутбуке, но передача
данных не ограничена локальной сетью.

Для подготовки используйте только нейтральные синтетические MOV. Раздел 10
кейса запрещает передавать тестовые видео третьим лицам: до использования
записей организаторов согласуйте допустимость такого маршрута с ними.
Если туннель не разрешён, нужен согласованный способ размещения с прямым
HTTPS-доступом. Не загружайте исходные банковские видео для проверки туннеля.

## 1. Подготовить ноутбук

Откройте PowerShell 5.1 или новее в корне репозитория. Нужны Python 3.12 x64
и доступ в интернет. Полная локальная самопроверка приложения выполняется
отдельно; для неё нужен также Node.js 22+:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check.ps1 -Install
```

Для первого внешнего запуска:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\public.ps1 -Install
```

`-Install` устанавливает зависимости приложения в `.venv-app` и утилиту
туннеля. Это не заменяет самопроверку и не устанавливает веса модели.
Рабочая `.venv` анализатора не используется. Если Python не найден, передайте
скрипту `-PythonPath` с полным путём к Python 3.12 x64.

Утилита `cloudflared` версии 2026.10.1 сохраняется только в
`.tools/cloudflared/cloudflared.exe`; установщик проверяет SHA256 официального
релиза. Служба Windows не создаётся. Можно установить её отдельно:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\install-tunnel.ps1
```

Источник программы и контрольной суммы:
[официальный релиз Cloudflare](https://github.com/cloudflare/cloudflared/releases/tag/2026.10.1).

## 2. Получить ссылку

Повторный запуск после установки:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\public.ps1
```

По умолчанию запускается `mock`, сценарий `multiple` с двумя событиями,
задержка анализа — 2 секунды. Приложение слушает только `127.0.0.1:8010`.
Туннель публикует именно этот экземпляр приложения; открывать порт роутера
или переводить backend на `0.0.0.0` не нужно.

Дождитесь сообщения о готовности и напечатанного HTTPS-адреса вида
`https://…trycloudflare.com`. Откройте эту ссылку вручную. Скрипт не открывает
браузер автоматически. Регистрация нового адреса в DNS может занять время:
проверка HTTPS ждёт до двух минут и при неудаче останавливает запуск.
Для показа ожидания можно увеличить задержку:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\public.ps1 -DelaySeconds 15
```

Это альтернативный запуск: сначала остановите предыдущий. Не запускайте
два экземпляра на одном порту. Если порт занят, выберите свободный параметром
`-Port`, например `-Port 8011`, не завершая чужие процессы.

Данные разделены по режимам:

| Режим | Каталог данных | API-ключ |
| --- | --- | --- |
| `mock` | `backend/.local/public-mock` | `backend/.local/public-mock/api-key.txt` |
| `real` | `backend/.local/public-real` | `backend/.local/public-real/api-key.txt` |

Каталоги содержат локальные задания и загруженные файлы; они исключены из Git.
Не публикуйте ключ, базу, загруженные видео и изображения. В браузер API-ключ
не передаётся.

## 3. Проверить HTTPS и API

Оставьте первое окно с приложением открытым. Во втором окне PowerShell,
из корня того же репозитория, введите напечатанный адрес:

```powershell
$publicUrl = Read-Host 'HTTPS-ссылка из окна запуска'
powershell -ExecutionPolicy Bypass -File .\scripts\check-public.ps1 -BaseUrl $publicUrl -ExpectMode mock -KeyFile .\backend\.local\public-mock\api-key.txt
```

Проверка создаёт нейтральные видео, обращается к внешнему HTTPS-адресу,
проверяет маршруты браузера и публичного API, загрузку, ожидание и структуру
результата. Ключ читается из файла и не печатается. Проверка не использует
банковские записи и не открывает браузер.

Успешный запрос с этого ноутбука подтверждает работу маршрута через внешний
адрес. Доступ из другой сети подтвердите отдельно на телефоне с мобильным
интернетом или ноутбуке Касымбека:

1. Откройте текущую HTTPS-ссылку и проверьте отметку тестового режима.
2. Загрузите нейтральный MOV. При запуске `mock` образец создаётся в
   `backend/.local/public-mock/sample.mov`; его можно передать на второе
   устройство. Подойдёт и нейтральный `sample.mov` этапа 8.
3. Дождитесь двух событий, откройте объяснения и увеличенные кадры.
4. Нажмите F5 и убедитесь, что готовый результат восстановился.

Если образца ещё нет, создайте его на нужном компьютере:

```powershell
.\.venv-app\Scripts\python.exe -m backend.make_sample --output .\backend\.local\public-mock\sample.mov
```

Восстановление привязано к браузеру и адресу сайта. Новый адрес Quick Tunnel
получит отдельные cookie и браузерное хранилище. Сохранённые в базе задания
сами по себе не означают, что прежняя браузерная проверка появится на новом
адресе. Во время демонстрации держите один запуск и одну ссылку.

## Доступ и размер файла

Интерфейс доступен всем, кто знает ссылку: они могут загрузить своё видео.
Браузерная сессия, проверка Origin и CSRF защищают связь с её заданиями, но
не заменяют вход по паролю. Ссылка не является секретным ключом. Публичные
маршруты `/api/v1/analyze` и `/api/v1/jobs/{job_id}` отдельно требуют
`X-API-Key`; передавайте ключ жюри согласованным закрытым способом.

Публичный запуск устанавливает предел **90 МиБ на файл**. Это оставляет запас
для multipart-запроса перед лимитом Cloudflare 100 MB. Локальный запуск по
умолчанию допускает 100 МиБ. Оба размера — настройки приложения, а не точная
верхняя граница кейса: в FAQ 25 приведены MOV около 29 МБ. Интерфейс получает
актуальный предел от сервера. Передача 100 МиБ через этот туннель не заявляется.
[Лимит Cloudflare](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/4xx-client-error/error-413/).

Quick Tunnel предназначен для временных показов, не гарантирует доступность
и ограничивает число одновременных запросов. Заранее проверьте связь в сети,
из которой будет проходить показ; ноутбук должен оставаться включённым,
подключённым к питанию и интернету. Для постоянного адреса требуется отдельное
решение размещения. [Ограничения сервиса](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

## 4. Остановить внешний доступ

Нажмите **Ctrl+C** в окне `public.ps1` и дождитесь завершения. Скрипт закрывает
свой туннель и свой сервер; внешний адрес перестаёт обслуживать приложение.
Локальные задания и результаты сохраняются. Затем можно закрыть окно.

Перед показом резервным вариантом остаётся локальная демонстрация:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\demo.ps1
```

Она открывается на `http://127.0.0.1:8000` и после установки зависимостей
не требует интернета. Локальный показ сам по себе не выполняет требование
кейса о публичном URL.

## Если внешний адрес не работает

| Ситуация | Действие |
| --- | --- |
| Не найдена `.venv-app` или утилита туннеля | Выполните `public.ps1 -Install`. Для повторного запуска установки не нужны. |
| Не найден Python 3.12 | Передайте `-PythonPath` с полным путём к установленному `python.exe`. |
| Используется другое отдельное окружение | Передавайте одинаковый `-VenvPath` скриптам запуска и проверки. Не устанавливайте зависимости поверх `.venv` анализатора. |
| Нужен собственный путь к утилите | Передайте `-CloudflaredPath` с полным путём к официальному `cloudflared.exe` версии 2026.10.1. Контрольная сумма проверяется и для этого пути. |
| Порт 8010 занят | Остановите свой предыдущий запуск или выберите другой свободный `-Port`. |
| Туннель не подключается | Проверьте интернет и сообщение об ошибке. Требуется исходящее TCP-соединение к Cloudflare на порт 7844. Не отключайте firewall; при блокировке согласуйте доступ с администратором сети. |
| Ошибка проверки контрольной суммы | Не запускайте файл. Сохраните отличающийся файл отдельно, затем повторите установку из официального источника. Установщик не перезаписывает существующий файл с другой суммой. |
| Старый адрес перестал открываться | Используйте ссылку текущего запуска. После остановки или создания нового туннеля прежний адрес использовать нельзя. |
| HTTPS открывается, но результат не появляется | Проверьте `/health`, режим сервера, сообщение приложения и вывод `check-public.ps1`. Сетевой сбой не означает отсутствие нарушений. |
| API возвращает 401 | Укажите ключ от текущего каталога `public-mock` или `public-real`. Ключ локального `demo` относится к другому экземпляру. |
| Сервер или прокси возвращает 413 | Проверьте размер MOV и текущий предел интерфейса. При превышении лимита не повторяйте ту же загрузку автоматически. |
| F5 не восстанавливает прежний отчёт | Проверьте адрес, браузер, cookie и срок хранения. Новый домен туннеля не переносит прежнюю браузерную сессию. |

Сетевые требования:
[Cloudflare Tunnel и firewall](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/configure-tunnels/tunnel-with-firewall/).

Это разовое измерение сетевой передачи и режима `mock`, не оценка скорости
реального анализа. Визуальную проверку в браузере и доступ из другой сети
нужно выполнить по шагам выше.

## Когда будет готов анализатор

Режим `-Mode real` предусмотрен для отдельного запуска после завершения
интеграции, согласования зависимостей и проверки настоящего анализа локально.
Сейчас наличие команды не означает готовность модели: отсутствующий
`analyzer/service.py` или ошибка загрузки должны останавливать подготовку,
а не включать тестовые ответы.

`check-public.ps1 -ExpectMode real` также отправляет нейтральные синтетические
видео. При готовой модели это проверяет передачу и контракт реального режима;
точность обнаружения кассовых нарушений по такому образцу не оценивается.

Перед финальной проверкой нужны согласованный маршрут для записей жюри,
готовый анализатор и измерения полного времени обработки. Успешный тест
туннеля подтверждает доступ к приложению, но не точность обнаружения нарушений
и не выполнение временного лимита реальной моделью.
